This ledger is the QA execution view of the specification. A row is a release condition when the source explicitly labels it **[确定]**, uses a binding “must/不得/不能” statement, or places it in the Core Release Gate. The page-information-architecture chapter is introduced as **[建议]**, but sections 10-A through the final release gate explicitly convert the listed page capabilities into first-release acceptance conditions; those later gates are treated as binding.

Recommendations that have not been promoted to a release gate are excluded here and recorded in [`architecture-decisions.md`](architecture-decisions.md). The specification's visual image is a reference, not a pixel-perfect implementation contract; where it differs from explicit text, the text wins.

**U1 — User correction, 2026-11-09:** physical Android-device install and runtime verification is explicitly waived by the user and is not a blocker. No Android device evidence is requested. Android CI Debug/Release APK build and artifact/release verification remain required, and an emulator, simulator, or virtual device must not be used as a substitute. `WAIVED` below records this user decision; it does not mean the row passed.

## Evidence Rules

Every row starts open unless U1 explicitly waives its remaining evidence gate. `PARTIAL` means an automated implementation test covers one or more specific bullets but the full row and its larger platform or integration gates remain open. Code presence, a design mock, a reviewer statement, or a successful build does not by itself close a row.

- **I — implementation test:** deterministic unit, contract, integration, migration, file-safety, accessibility, or UI-component test in the implementation environment.
- **CI — CI gate:** GitHub Actions check/build/artifact/release evidence from the repository.
- **W — Windows device gate:** manual evidence from an installed build on a real Windows environment.
- **A — Android device gate:** **WAIVED by U1 on 2026-11-09.** Do not require an APK installed on real hardware and do not substitute an emulator, simulator, or virtual device. Android CI/artifact gates remain active.
- **X — cross-device gate:** two physical devices using one real cloud Provider Profile, with upload/download and conflict evidence.
- **V — visual review:** screenshots or recordings from the running app in the required sizes, themes, states, and inputs.

Pass evidence must identify the build/revision, platform and OS version, data set, gate, observed result, and artifact/log/screenshot location. A higher gate cannot be closed by a lower one. A row is marked `WAIVED` only where U1 removes its remaining evidence gate; lower implementation or CI gates continue to apply. Accessibility may combine implementation checks with supported-platform or visual evidence where the row requires it.

Source references use one-based line numbers in the authoritative source file. `L5, L11-18` means lines 5 and 11 through 18 of that file.

## Highest-Risk Acceptance Gaps

- **Data-loss and deletion semantics:** local-root unavailability, migration interruption, managed-versus-external deletion, and tombstones require fault-injection tests and two-device evidence before release.
- **PDF write-back:** standard annotations can pass UI tests while still being nonportable or corrupting files. External-reader verification plus interruption, disk-full, read-only, backup, validation, Hash, and sync tests are all required.
- **Android SAF versus database semantics:** the app must keep transactional data off arbitrary Document URIs and survive revocation/restart without issuing destructive sync updates.
- **Offline-first conflicts:** progress, tags, bookmarks, annotations, sessions, settings, and Markdown notes need entity-specific convergence with no silent overwrite and no trust in wall-clock timing alone.
- **Plugin security boundary:** Cordis is not a sandbox. Full Vue pages, untrusted Worker/iframe pages, Tauri capabilities, Host API permissions, credential secrecy, and lifecycle cleanup need explicit security tests.
- **Platform behavior still in scope:** real Windows removable media, Credential Manager, desktop input, window resizing, and file-access behavior remain required. Android physical behavior is waived by U1, but CI APK checks remain required and emulator evidence is prohibited.
- **Release infrastructure:** signing secrets, GitHub Actions release permissions, and a real S3/WebDAV account have not been evidenced. The exact credentials must remain external to the repository.
- **Unresolved product decisions:** minimum supported Windows/Android versions, Windows packaging/distribution, performance thresholds, and specialized stylus behavior are not settled by the specification. They should not be guessed into the acceptance baseline.
