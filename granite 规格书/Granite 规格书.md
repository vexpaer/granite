# 定位与确定决策

Granite 是免费开源、Local-first、插件优先的跨平台电子书阅读器与个人图书管理系统。Granite 为正式项目/产品名称；本文中的 Reader 在指阅读功能或阅读器子系统时保留该术语。第一版交付平台仅包括 **Windows 桌面端与 Android**；Linux 暂不纳入首版支持、测试或发布范围，后续可作为独立阶段评估。桌面端使用 **Rust** 作为原生宿主和系统能力层，插件运行时采用 **Cordis**。目标是尽可能轻量、可离线使用、用户数据自持、无需官方账号或强制自建服务器。首版通过用户配置的单一 S3-compatible 或 WebDAV Provider 连接多个设备；Google Drive 和 OneDrive 作为可安装的后续 Provider 插件扩展，不纳入首版必备连接器。Windows 与 Android 均必须在设置中提供可选择、查看和更改的本地书库文件夹。暂不要求 Web 阅读端。

本文描述完整的目标系统、约束和接口，不按开发阶段拆分。标记 **[确定]** 表示用户已明确决定，**[建议]** 表示推荐技术方案，**[待定]** 表示需用户决定。不要把建议或待定视为用户已批准。

# 一、产品原则

- 开源、免费、可自建数据存储；主项目许可证采用 AGPL-3.0（按用户「最开源」目标解释为最强 Copyleft）；第三方插件需单独声明许可证并检查分发兼容性；无强制账户、订阅或开发者云服务。
- Local-first：断网时能阅读、编辑书库、记录进度、标注和笔记；联网后同步。
- 跨端一致：Windows 与 Android 共享数据模型、业务逻辑、插件 SDK 和核心产品体验；平台导航、输入和系统能力按各自环境适配。
- 尽可能轻量：避免 Electron、完整 Node.js 运行时、常驻本地服务器和不必要的后台任务。
- 插件优先：计时、阅读统计、笔记本、AI、主题、存储连接器、书源等尽量插件化。
- 开放数据：用户可完整导出书籍、元数据、笔记、标注、设置和插件数据。
- 插件可扩展 UI，用户可自定义工作区、侧栏、工具栏、阅读面板、仪表盘和主题。
- 不能让插件故障或云存储不可用阻止用户本地阅读。

# 二、技术架构

**[确定]** 首版交付 Windows 与 Android；Windows 桌面端以 Rust 承担原生宿主；插件框架采用 Cordis；跨平台 UI 采用 Tauri 2 + Vue 3 + TypeScript；Android 构建、自动化测试与发布使用 GitHub Actions；首版云存储为 S3-compatible 与 WebDAV，文件与同步元数据必须使用同一个 Provider 配置；首版核心格式原生支持 EPUB、PDF、TXT、MOBI；PDF 标注必须直接写回 PDF 文件；Notebook 采用 Obsidian 风格的 Markdown、文件夹和双向链接；Windows 与 Android 均允许用户设置本地书库文件夹；正式项目名称为 Granite。

**[确定]** 采用 Tauri 2 + Rust Host + Vue 3 + TypeScript UI + Cordis Core。**[建议]** 本地结构化数据使用 SQLite。Tauri 使用平台系统 WebView，避免 Electron 的 Chromium/Node 负担。Windows 使用 WebView2，Android 使用 Android System WebView。Cordis 是 JS/TS 框架，运行在跨平台 JS 环境；Rust 负责原生文件、数据库、网络和安全凭证等能力。桌面完全 Rust 原生 GUI 不再作为并行的默认设计方案。

架构分层：

1. Platform Host：Tauri/Rust，文件系统、SQLite、HTTP、凭证、通知、系统文件选择器、Android 生命周期。
2. Domain Core：书籍、书架、标注、进度、阅读位置、搜索、导入导出等稳定领域接口。
3. UI Shell：Vue 组件、阅读器、书库、设置、插件 UI Slot、布局与主题。
4. Cordis Runtime：Context、Service Registry、依赖注入、事件、生命周期和作用域。
5. Plugin SDK/Loader：插件 Manifest、权限、依赖、安装、加载、卸载、兼容性和 UI 扩展。
6. Storage Provider：首版内置 S3-compatible、WebDAV、本地文件系统；Google Drive、OneDrive 等通过后续 Provider 插件扩展。
7. Sync Engine：离线队列、设备同步文档、增量交换、合并、冲突、删除墓碑。
8. Official/Third-party Plugins：功能、Provider、格式、主题、知识管理等。

模块依赖方向：UI 只能通过领域 API 和 Host API 访问数据；插件通过 Context 访问服务；Sync Engine 依赖统一 Provider 接口，不依赖特定云服务；Rust 不依赖 Vue 组件；插件不能直接 import 其他插件私有实现。

# 三、轻量化与平台约束

- 不使用 Electron，不要求 Node.js 常驻、不要求 Redis/PostgreSQL/Docker。
- 大型书籍流式读取，按需下载，封面与缩略图缓存；书库列表虚拟化。
- 插件懒加载，禁用插件不加载；高频位置和滚动事件节流；索引和同步可取消。
- Windows：拖拽导入、文件选择器、键盘快捷键、窗口状态保存、Credential Manager。
- Android：Storage Access Framework、系统分享导入、Keystore、触控与系统返回、前后台切换、进程回收、系统后台同步限制。
- Android 不假设 Node.js、任意文件路径或无限后台运行能力。
- 记录安装包、启动时间、空闲内存、打开大书峰值内存、同步网络与电量开销；性能目标用实测基准定义。

# 三-A、跨平台书库（仓库）文件夹设置：强制要求

**[确定]** Windows 与 Android 两个首发平台都必须在应用设置中提供「本地书库文件夹 / Library Folder」的可见入口，允许用户选择、查看、修改和重新授权本机用于存放书籍文件的目录。不能只在桌面端提供，也不能仅在首次安装时设置；应用使用期间可随时重新配置。

## 用户交互契约

- 固定入口：「设置 → 书库 → 本地书库文件夹」。显示当前目录名称或可识别位置、访问状态、剩余空间（能够取得时）、打开/选择/更改操作。
- 首次启动提供合理默认目录，用户可直接使用或自主选择。
- 必须允许用户选择既有文件夹而非只能在应用沙盒新建目录。
- 选择后确认读写权限，明确当前采用「导入现有内容 / 更改工作书库 / 迁移现有书库」哪种行为；不得静默覆盖目录、合并不同书库或移动原文件。
- 更改目录时提示是否迁移本地受管书籍和相关附件，支持可取消的安全迁移、进度、校验与错误恢复。源目录在新目录校验完成前不得自动删除；迁移失败保留原目录。
- 目录丢失、外置磁盘卸载、Android 授权失效或权限变更时，显示「书库不可访问」并支持重新授权/重新定位；不得把不可访问误判为用户删除书籍，从而生成跨设备删除墓碑。
- 区分「书库根目录」与「最近导入位置」；导入来源不自动变为本地书库根目录。允许通过系统文件选择器导入外部书籍。
- 书库文件夹由设备单独配置；同步设置时不得把 Windows 盘符路径覆盖 Android SAF URI。不同设备的目录位置可以不同，但书籍身份与云同步协议保持一致。
- **[确定] 同一设备必须允许同时配置多个独立书库根目录**（Windows 与 Android 均适用）。用户可「添加文件夹」「移除文件夹（仅解除关联）」「重命名显示名」「设为默认导入文件夹」「临时禁用扫描」「重新扫描」「重新授权」；所有根目录聚合成统一书架，同时支持按来源文件夹筛选。添加新的既有目录时只索引/导入其现存书籍，不自动移动或删除原文件。
- 根目录有稳定 libraryRootId、设备本地路径/URI、显示名、权限状态、扫描状态、默认导入标记、只读标记（如适用）；一本书记录来源 rootId 和相对引用。路径/SAF URI 不跨设备同步，书籍逻辑身份与阅读进度可同步。
- 移除根目录默认仅解除本机索引与访问关系，不删除磁盘文件、云端书籍或其他设备记录，不产生远端删除墓碑；真正删除书籍需单独明确操作。根目录暂时不可访问时不得误触发删除。
- 在不同根目录间移动书籍需要明确的复制/移动流程，完成后校验内容和关联数据；同内容多根目录出现时显示重复来源，不擅自删除任何副本。

## 平台实现契约

- Windows：使用系统原生文件夹选择器；支持绝对路径、Unicode、长路径、网络/可移动卷的错误提示与重新选择；读写前验证权限。
- Android：通过 Storage Access Framework 的 ACTION_OPEN_DOCUMENT_TREE 或适用的系统目录授权机制选择文件夹，保存持久化 content URI Tree 授权；应用重启后尝试恢复授权。Android 不得把 SAF URI 伪装为普通 POSIX 路径，不得假定对任意目录拥有直接文件系统权限；需经 ContentResolver、DocumentFile 或适配的原生桥接层读写。部分受保护目录不可选，由系统限制决定。
- Android 的受管书籍可放在用户授权的目录中；SQLite 的活动数据库、事务日志、插件运行缓存和安全凭证应放在可可靠随机访问、保证事务语义的应用私有存储中，不能直接把 SQLite 活动数据库打开在通用 SAF Document URI 上。必要时通过清单/备份导出向用户提供完整数据可迁移性。
- 各平台原生目录访问通过统一 LibraryRootService / FileHandle 抽象实现；插件只获得经过授权的书籍句柄或带权限限制的存储 API，不暴露整个根目录的无限制读写权。

## 数据与同步契约

- 本地书库设置包含 deviceId、平台特定目录引用、授权状态、目录类型、最近成功校验时间和本机迁移状态；路径/URI 视为仅本机配置。
- 数据模型用稳定的逻辑 bookId、内容 SHA-256 和相对书库引用，不在跨设备同步文档中硬编码 Windows 本地路径或 Android SAF URI。
- 同步引擎通过 LibraryRootService 获取本机文件句柄，支持流式读取、分块 Hash、上传和安全下载落盘；云端连接器与本地目录配置相互独立。
- 更改书库目录不能改变用户的云端 Provider 绑定，也不能自动触发云端批量删除。确认某文件确实删除与临时不可访问是不同状态。
- Notebook 插件默认应可把 Markdown 笔记保存在所选书库的可访问子目录，保持可迁移性；当平台权限、性能或用户偏好不允许时，必须清楚展示实际数据目录并提供导出/迁移方式，不能误导用户以为所有内容都存入选中的文件夹。

## 测试与验收

- Windows 与 Android 的设置页面均能打开对应的原生目录选择器、保存设置、重启后恢复可访问性并成功读写一本 EPUB/PDF。
- 从旧目录切换到新目录时，书籍、阅读状态与标注不丢失；迁移中断后能恢复或回退。
- Windows 外置盘移除、Android SAF 权限被撤销时，书库不会被误判为空并同步删除全部书籍。
- Android 可在允许的 SAF 目录中存取书籍，且 SQLite 事务不依赖对 SAF 文件的随机访问。
- 两台设备使用不同文件夹路径时，同一书籍仍通过逻辑 ID/内容 Hash 正确同步进度与标注。

# 四、Cordis 插件系统

**[确定]** 使用 Cordis 作为插件架构基础。其 Context、Service、Events、Dependency Injection、Reversible Effects、Lifecycle 和 Scoped Context 用于组织插件。Cordis 本身不提供完整安全沙箱、Vue UI Slot、插件商店或 Android 原生文件访问。

**[建议]** Granite Plugin SDK 对 Cordis 进行封装，第三方插件只依赖 Reader 的稳定公开 API，避免 Cordis 版本升级直接破坏插件。

跨平台 Loader：不直接依赖 Node.js 专属的 @cordisjs/plugin-loader；通过 Rust/Tauri 文件接口发现插件，解析 Manifest、校验版本与依赖、读取预构建 ESM Bundle，交给 Cordis 运行时激活。检查循环依赖、权限、API 版本和目标平台。插件停止时必须撤销事件、命令、UI、定时器和资源注册；失败插件可单独禁用，支持安全模式启动。

Plugin Context 建议服务：

- ctx.reader：当前书籍、阅读位置、文本选择、阅读控制。
- ctx.library：书籍查询、导入、元数据、标签、集合。
- ctx.annotations：书签、高亮、批注。
- [ctx.events](http://ctx.events)：类型化事件订阅与发布。
- [ctx.storage](http://ctx.storage)：插件私有持久化空间。
- ctx.sync：插件命名空间同步及冲突策略。
- ctx.ui：注册页面、Widget、菜单、工具栏、面板。
- ctx.commands：命令和快捷键。
- ctx.settings：插件配置与 Schema。
- ctx.scheduler：可暂停取消的任务。
- ctx.notifications、ctx.permissions、ctx.logger。

Manifest 至少包含 id、name、version、apiVersion、main、dependencies、optionalDependencies、permissions、contributes、platforms、schemaVersion、author、license、repository、integrity。插件 ID 稳定唯一，语义化版本，声明依赖和权限，校验兼容性。官方和第三方插件使用相同 SDK。

插件类别可重叠：Feature、Core Extension、Storage Provider、Sync Provider、Format、Import/Export、UI、Theme、Integration。允许插件向其他插件提供 Service，但不得直接访问其他插件的私有数据库。

安全：Cordis Context 不是沙箱。插件允许提供完整自定义 Vue 页面，而不局限于预置 Slot 中的简单 Widget；插件可携带 Vue/ESM 页面 Bundle，并通过 Granite Plugin SDK 注册页面、路由、面板、工具栏和设置 UI。允许从官方目录、第三方插件目录/Registry、Git 仓库或 Release、用户提供的 URL、以及本地插件包安装第三方插件。安装前必须展示来源、作者、版本、完整性/签名状态、API 兼容性、许可证和权限，并由用户明确确认。可信或用户明确授权的插件可在受控 Vue 扩展运行环境中呈现完整页面；未信任代码默认隔离在 Worker/iframe 或其他受控环境中，通过 RPC 调用经过权限检查的 Host API。完整 Vue 页面也不能绕过 Tauri capability、Host API 权限和文件访问边界。权限至少区分 `reader.observe`、`reader.control`、`library.read`、`library.write`、`bookfile.read`、`bookfile.write`、`annotation.read`、`annotation.write`、`network.request`（限制目标）、`storage.namespace`、`sync.namespace`、`ui.register`、`notification`、`credential.use`。不得将明文密钥暴露给插件；权限可撤销。插件禁用或卸载默认保留数据；插件未安装的设备也不能删除其同步数据。

# 五、可定制 UI

UI Shell 定义稳定的 Slot Registry，支持：

- app.sidebar、app.dashboard、app.header.actions、app.command-palette
- library.toolbar、[library.book](http://library.book).context-menu
- reader.toolbar、reader.left-panel、reader.right-panel、reader.bottom-panel
- reader.selection-menu、reader.status-bar、settings.pages

插件可贡献页面、面板、工具栏按钮、上下文菜单、Widget、设置页和主题。每个扩展有 ID、标题、图标、排序、显示条件、尺寸与平台兼容声明。用户可拖动、隐藏、调整宽度和顺序，布局可同步和导出。Android 必须遵循「竖屏底部主导航、横屏左侧 Navigation Rail、平板/大屏自适应侧边导航」的统一响应式规则；详见「Android 自适应方向与导航布局」。

主题通过设计 Token 控制色彩、字体、字号、行距、边距、圆角、密度、深浅色和书页背景，不默认允许第三方插件任意覆盖全局 CSS。提供 Minimal、Research、Knowledge、Dashboard、Custom 等 Profile；Profile 保存插件启用状态、布局、主题和插件设置。缺失插件不能破坏其他 UI。

## Android 自适应方向与导航布局

**[确定]** Android 必须完整支持竖屏与横屏两种布局。竖屏手机使用五项底部主导航；横屏手机将主导航移至左侧；平板/大屏根据可用宽度使用侧边 Navigation Rail 或可展开 Navigation Drawer。三种布局共享同一套页面目的地、数据和功能。

- **竖屏（手机默认）**：底部固定五项导航，顺序为「主页、书架、笔记、统计、我的」，不得将「我的」收纳到更多菜单。每项包含图标与短标签，当前项有清晰选中态。页面顶部保留标题、搜索和当前页面必要操作；内容以单列纵向滚动为主。
- **横屏（手机横置）**：主导航切换为左侧 Navigation Rail，五个目的地仍可直接访问；内容区域使用剩余宽度。空间允许时，书架、Notebook 和设置可采用主从双栏。
- **平板与大屏**：使用侧边 Navigation Rail 或可展开 Navigation Drawer；书架可采用多列封面布局，Notebook 可采用列表 + 编辑器双栏，设置可采用分类 + 内容面板。不得将手机单列页面简单拉宽。
- **布局切换依据**：优先依据可用窗口宽度/Android Window Size Classes，而非仅检测设备型号或方向。分屏、多窗口、折叠屏和自由窗口也必须适配。
- **导航状态**：切换横竖屏、分屏或窗口尺寸时保留当前目的地、每个主导航项的返回栈、列表滚动位置、搜索条件、选中项和未提交编辑内容；不得因布局重建回到首页或丢失状态。
- **「我的」页面**：作为 Android 竖屏的第五个一级目的地，承载个人资料、同步与存储、书库文件夹、插件中心、阅读偏好、标签管理、应用设置、关于与诊断。设置和同步不再单独占用底部导航。
- **插件导航**：插件可贡献页面或入口，但默认不得挤占五个核心导航项；插件入口放在「我的 → 插件中心」，用户主动固定后才可获得额外快捷入口。
- **阅读器例外**：进入沉浸式阅读后隐藏底部/侧边主导航，阅读画布占据可用区域；屏幕旋转后恢复同一文档锚点、PDF 二维平移偏移和缩放比例。阅读工具栏依据横竖屏与可用空间调整位置，不能覆盖主要阅读区域。
- **Windows 桌面端**：使用四项侧边主导航「主页、书架、笔记、统计」，账户/设置/同步从头像菜单进入；Windows 与 Android 共享页面目的地和领域模型。

# 五-A、页面信息架构与交互导航

**[建议]** 本章定义 Reader 的标准页面清单、页面层级、导航目的地、页面间跳转和交互状态，作为 UI Shell 与各平台页面实现的共同契约。页面结构由本章约束；颜色、字体、形状、组件和动效由「六-B、视觉方向与设计系统」约束。实现时两章必须同时遵守。

## 1. 信息架构原则

- 先按用户任务组织页面：阅读与管理书籍、整理知识、查看阅读进度、管理扩展和配置应用。
- 区分一级导航目的地、二级页面、详情/编辑页面、全屏工作区和临时浮层；不得把所有功能平铺在首页或主导航。
- Windows 与 Android 共用稳定的页面 ID、领域数据和主要任务流程；导航容器与输入行为按平台自适应。
- 核心页面不依赖插件才能访问。插件可以增加页面、面板和 Widget，但不能替换或破坏书架、阅读器、Notebook、设置等核心能力。
- 页面跳转应保留用户上下文：返回时恢复来源页面、筛选条件、滚动位置、选中项、搜索词和未提交编辑。
- 每个页面都必须定义正常、加载、空、离线、错误、权限不足、只读、选中和未保存等适用状态；不能只设计成功状态。
- 全局搜索、命令面板、导入流程、确认对话框和上下文菜单属于全局操作或临时界面，不应全部注册为一级导航目的地。

## 2. 默认一级导航

**[确定]** 桌面端左侧主导航固定为以下四项，顺序如下：

1. **主页（Home，route: `home`）**：阅读工作台，展示继续阅读、最近阅读、最近笔记、阅读统计、今日目标和常用标签。
2. **书架（Library，route: `library`）**：可展开/收起的导航组，展开后固定显示「全部、阅读中、未读、已读、收藏」五个子项；书架内容区另支持集合、标签、来源文件夹、排序和筛选。
3. **笔记（Notebook，route: `notebook`）**：独立的 Markdown 知识空间，不要求用户先打开一本书。
4. **统计（Statistics，route: `statistics`）**：阅读时长、日历、连续阅读、书籍进度、目标和报告。

**设置与同步统一收纳在左下角头像菜单中**，不占据左侧一级导航位置。头像菜单至少提供「账户/个人资料」「设置」「同步与存储」和「关于/诊断」入口；设置内继续管理通用、外观、书库、阅读器、插件中心与权限、快捷键和数据备份。插件中心从「头像菜单 → 设置 → 插件」进入。

全局搜索在顶栏、快捷键和命令面板中可随时调用，不占用一级导航位置。插件不得默认挤占四个核心导航项；插件页面只有在用户主动固定后才能获得快捷入口。

## Android 竖屏 UI 规格（五个底部导航页面）

**[确定]** 本节定义 Android 手机竖屏的首版视觉与页面结构。底部导航固定为「主页、书架、笔记、统计、我的」五项。页面采用白色/浅色背景、清晰的紫色强调色和精致但克制的卡片层次；本节是供开发 Agent 实现的文字规格，不依赖设计稿图片。

### 1. 全局布局与视觉规则

- **页面画布**：Light 模式下主内容背景默认纯白或接近白色的中性白；卡片可使用轻微暖白/浅灰表面、柔和阴影、细边框、圆角和浅紫色强调。不得把整页铺成复杂渐变背景。Dark 模式另行映射颜色 Token。
- **视觉方向**：沿用 Granite 已确认的 Reeden 参考方向和「精致、安静、可定制的数字书房」定位。允许高质量卡片、柔和渐变、半透明材质和细腻动效；禁止无意义的小字、重复副标题、装饰性标签和虚构数据。
- **品牌与山峰背景**：主页可使用默认雪山图作为顶部欢迎区域/横幅背景，并允许用户自定义或恢复默认图。山峰图不得铺满所有页面，也不得影响标题、书籍封面和正文可读性。其他页面默认保持白色内容画布。
- **页面安全区**：正确处理状态栏、刘海/挖孔、手势导航区和底部系统安全区。底部导航固定在应用内容底部并避开系统手势区域；滚动内容不得被导航栏遮挡。
- **页面滚动**：各页面正文独立纵向滚动；底部导航固定不随内容滚动。打开详情、筛选或返回时恢复来源页面滚动位置。
- **顶部栏**：显示当前页面标题和该页主要操作。搜索、添加、更多等图标按钮放在右侧；无对应操作时不占位。右上角同步成功状态仅显示简洁的绿色「✓」图标；其他同步状态使用可辨认的状态图标。同步详情统一从「我的 → 同步与存储」进入。不得增加通知铃铛或全屏按钮。
- **底部主导航**：顺序固定为「主页、书架、笔记、统计、我的」，每项等宽，图标在上、短标签在下；选中项使用紫色强调，未选中项使用中性灰/深灰。触控区域满足 Android 无障碍尺寸要求，图标与标签对齐，不使用大面积胶囊背景或夸张装饰。五项始终可见，不横向滚动、不折叠。
- **卡片与文字**：卡片按内容分组，不要求所有内容都装入卡片；标题、书名、关键数值保持足够字号。辅助信息仅在能帮助识别、决策或操作时出现。长标题最多按合理行数截断，并提供详情查看。
- **圆形进度系统**：Granite 的进度指示统一使用圆环，不使用横向或纵向直条进度条。书籍卡片中的紧凑进度采用「百分比文字在左、微型圆环在右」的组合；圆环直径与百分比文字高度基本一致，圆环填充比例与百分比数值一致。已读书籍只显示「已读」，不显示百分比或圆环。首页阅读目标和统计目标使用较大圆环；导入/同步等有明确完成比例的任务也使用圆形进度指示。时间趋势柱状图、日历热力图等数据图表不属于进度条，可以按数据表达需要使用。
- **操作反馈**：收藏、标注、标签修改、目标完成、保存、同步等操作必须有即时反馈；错误状态提供重试/恢复入口。避免只用颜色表达状态。
- **适配宽度**：至少在约 360 dp、390–400 dp 和更宽手机窗口测试。常规手机书架默认三列封面网格；可用宽度不足、系统字体放大或卡片内容无法清晰呈现时自动降为两列，不得挤压文字或缩小封面到不可辨认。

### 2. 主页（Home）

**页面目标**：让用户快速继续阅读、浏览最近内容、查看目标和进入常用标签。

- 顶部欢迎区：显示 Granite 品牌/欢迎语；可叠加用户自定义的雪山背景图。背景以柔和渐隐方式过渡到白色内容区。
- 继续阅读：展示最近正在阅读的一本书，包含封面、书名、作者（有数据时）、阅读进度和「继续阅读」入口。进度使用百分比 + 微型圆环或适合空间的大圆环，不使用直条。
- 最近阅读：以紧凑封面网格或横向列表展示最近打开的书；每本书显示封面、书名和阅读状态/进度。点击封面或书名进入书籍详情，明确的继续阅读操作直接进入 Reader。
- 最近笔记：显示最近编辑的若干条笔记，包含标题、更新时间和一行有意义的摘要；点击进入对应笔记。
- 阅读目标：以大尺寸圆环展示今日/本周期目标完成比例，并显示已完成时长与目标时长；点击进入统计页的目标详情。
- 我的标签：显示常用/置顶标签，点击进入标签结果页；提供「管理标签」入口。
- 模块可按用户偏好或 UI 插件调整顺序、显隐和数量；默认布局必须完整可用，不能依赖插件显示上述核心模块。
- 空状态：无书籍时提供导入入口；无笔记时提供新建笔记入口；未设置目标时提供设置目标入口；无标签时提供创建标签入口。

### 3. 书架（Bookshelf）

**页面目标**：快速浏览、查找、筛选和管理书籍。

- 顶部栏：标题「书架」、搜索入口、添加/导入入口；更多菜单可提供视图切换、排序和批量管理入口。
- 状态筛选：提供「全部、阅读中、未读、已读、收藏」快捷筛选，窄屏允许横向滑动筛选项；当前筛选状态清晰可见。
- 标签与高级筛选：支持按标签、集合、作者、格式、来源文件夹等筛选；支持多条件组合、清除筛选和排序。常用标签可以以小型 Chip 呈现，但不得占据大量垂直空间。
- 书籍展示：默认三列封面网格，封面保持原始比例，卡片不强制套用厚重边框。可切换列表视图；列表视图展示更多元数据。
- 书籍卡片：封面下方依次显示书名与进度/状态。未读可显示「未读」；阅读中显示「67%  ○」式百分比 + 微型圆环；已读显示「已读」。百分比文字与圆环同色系、同一视觉行，圆环直径与文字高度接近。收藏状态可通过轻量图标表达，不覆盖书名。
- 点击封面/书名进入书籍详情；卡片的明确「继续阅读」动作进入 Reader。长按进入多选模式；多选后显示批量标签、集合、状态和删除等操作。
- 底部导航始终可见；书架列表滚动不带动底部导航。
- 空状态提供导入书籍与选择书库文件夹入口；加载失败、文件丢失、无匹配筛选结果均提供明确提示和恢复操作。

### 4. 笔记（Notebook）

**页面目标**：提供独立的 Obsidian 风格 Markdown 知识空间，并让用户快速访问笔记、摘录和书籍关联内容。

- 顶部栏：标题「笔记」、搜索、更多/筛选入口；右上角可提供新建笔记按钮。新建操作必须始终容易发现。
- 内容分类：默认提供「全部笔记」以及按需展示的「文献笔记、摘录」等快捷视图；具体分类来自笔记类型/标签，不应把示例类别写死为不可配置分类。
- 笔记列表：以纵向列表为主，每条包含笔记图标/类型标识、标题、最近更新时间和简短正文摘要；有关联书籍时显示书籍来源。摘要应截断，不得缩小字号塞入过多文字。
- 标签与文件夹：支持标签筛选、文件夹浏览和排序；手机上使用全屏子页面或 Bottom Sheet 展示复杂目录，不在主列表长期占用侧栏宽度。
- 笔记编辑：点击笔记进入全屏编辑页；提供 Markdown 编辑/预览切换、返回、保存状态、附件、标签、双链/反向链接和关联书籍入口。键盘弹出时编辑区域自动适配，工具栏不遮挡光标。
- 新建笔记可从空白笔记、书籍详情、Reader 选中文字和摘录操作进入；从 Reader 创建时必须保存书籍 ID、原文引用和 ReaderLocation。
- 空状态提供新建笔记和导入 Markdown 入口；搜索无结果、附件丢失、同步冲突和保存失败均可恢复。

### 5. 统计（Statistics）

**页面目标**：用直观、可解释的图表呈现阅读习惯、时长、进度和目标。

- 顶部栏：标题「统计」；时间范围切换「周、月、年」，默认展示本月；切换后所有汇总和图表使用同一时间范围。
- 概览卡片：展示本周期阅读时长、读完书籍数等核心指标。指标数量保持克制，点击指标可进入明细。
- 阅读目标：使用醒目的大圆环显示目标完成百分比，圆环中心展示百分比/目标名称；旁边或下方列出已读时长、目标时长和剩余时长。不得使用横向进度条。
- 阅读分布：使用环形图展示按标签/类别/作者等维度的阅读时间分布；图例显示名称和占比，点击分区可下钻。
- 趋势与日历：展示日/周阅读时长趋势、阅读日历/热力图、连续阅读天数和会话记录。柱状图仅用于表达随时间变化的数据，不用作任务进度条。
- 书籍进度：可查看正在读、已读和待读书籍；单本进度继续使用圆环或百分比 + 微型圆环。
- 空状态：没有阅读会话时显示开始阅读/导入书籍入口；统计不足一个完整周期时明确显示已有数据范围，不补造趋势。

### 6. 我的（Me）

**页面目标**：集中管理个人资料、书库位置、同步、插件和应用配置。它是 Android 竖屏第五个一级页面。

- 个人资料区：显示用户头像和可编辑显示名称；可显示本地用户配置/账户信息（若启用），不得要求用户注册 Granite 官方账户才能使用本地阅读功能。不要展示虚构会员等级、积分或订阅状态。
- 书库位置：显示当前书库仓库文件夹/根目录的名称与位置摘要，点击进入文件夹设置；所有平台都必须允许用户设置书库文件夹。
- 同步与存储：显示当前 Provider 名称和简要连接状态；点击进入 Provider 配置、同步策略、同步历史、队列和冲突处理。成功状态可用简洁勾号表示，错误/离线状态必须可辨认。
- 插件中心：进入插件发现、已安装、更新、权限和插件详情。
- 阅读偏好：进入阅读器默认字体、字号、行距、边距、阅读主题、手势和工具栏偏好。
- 标签管理：进入全局标签管理，支持创建、重命名、改色、合并、删除和查看关联书籍/笔记。
- 设置：进入通用、外观与布局、书库、阅读器、快捷键、数据与备份等设置分类。
- 关于与诊断：显示 Granite 版本、开源许可证、运行环境、诊断日志和用户主动导出的诊断包。
- 菜单项采用清晰的分组列表和轻量图标；每行整行可点击，显示标题与必要的当前状态/辅助信息。设置、同步、插件中心不得另占底部一级导航位置。

### 7. 竖屏导航与页面跳转

- 点击底部五个目的地直接切换页面；每个目的地维护独立返回栈、滚动位置和筛选状态。
- 从书架打开书籍详情，再进入 Reader；返回时回到原书架筛选和滚动位置。
- 从 Reader 创建笔记进入 Notebook 编辑页；返回时可回到 Reader 原位置，引用关系保持完整。
- 从主页标签进入标签结果页；返回主页时保留首页滚动位置。
- 从统计指标进入明细后返回统计，保留时间范围和滚动位置。
- 从「我的」进入设置、同步或插件子页后，系统返回回到「我的」原位置。
- Reader 沉浸式阅读时隐藏底部导航；系统返回先关闭临时面板/搜索/目录，再退出 Reader，避免直接丢失阅读上下文。
- Android 系统返回、边缘返回手势和应用内返回按钮必须遵循同一导航栈，不得产生重复页面或意外回到首页。

### 8. 竖屏页面验收

- 在 360 dp 与 390–400 dp 手机宽度、竖屏、Light/Dark、大字体和系统导航手势模式下逐页检查五个页面。
- 五项底部导航顺序、图标、标签、选中态、触控区域和安全区正确；任何页面均可在一次点击内切换一级目的地。
- 主页继续阅读、最近阅读、最近笔记、阅读目标和标签入口都能跳转到正确页面。
- 书架三列/两列自适应正确；书籍卡片百分比与微型圆环一致，已读状态不显示圆环；筛选、搜索、列表/网格切换和批量操作有效。
- Notebook 列表、编辑器、Markdown 预览、附件和双链在软键盘弹出/收起时不丢失输入或遮挡光标。
- 统计的时间范围切换、目标圆环、分布环形图和趋势图与原始 Reading Session 数据一致。
- 「我的」中书库文件夹、Provider、插件、标签和设置入口均可达；不需要官方账户即可使用本地核心功能。
- 所有页面滚动时底部导航保持固定；横竖屏切换、分屏和系统返回后，页面、筛选、编辑内容和滚动位置正确恢复。
- 没有无意义的小字、虚构会员信息、假按钮、假进度或缺少结果反馈的操作。

### 页面定位

首页是 Granite 的阅读工作台，负责帮助用户快速回到正在阅读的书、查看近期阅读与笔记、了解阅读目标和访问常用标签。它不是管理后台式数据仪表盘。

### 桌面端整体布局

- 首版优先完成 Windows 横屏桌面布局；以宽屏应用窗口为基准，采用左侧固定导航栏 + 右侧主内容区。
- 左侧导航栏保持稳定宽度；右侧内容区随窗口宽度扩展，卡片在宽屏中采用两列或三列组合布局。
- 首页顶部主内容区域保留横向雪山景观作为欢迎区背景，与左侧雪山背景形成统一视觉。
- 搜索框位于主内容区顶部靠左；右上角仅保留同步状态指示，不显示通知铃铛或全屏/窗口按钮。同步状态的具体显示规则见下方「顶部搜索与同步状态」。

### 左侧导航栏（全局固定结构）

1. **主页**：当前首页目的地。
2. **书架**：可展开/收起；展开后显示「全部、阅读中、未读、已读、收藏」五个固定子项。
3. **笔记**：进入 Notebook。
4. **统计**：进入阅读统计。

设置与同步不出现在左侧导航；统一放在左下角头像菜单中。头像菜单至少包含「账户/个人资料」「设置」「同步与存储」「关于/诊断」。

导航视觉要求：

- 左上角不放独立 Logo 图标；显示品牌文字「Granite」。
- Granite 品牌字使用优雅、有辨识度的高质感字体，偏编辑式/衬线展示字体；具体字体家族待设计实现时选型。
- 左侧默认使用雪山图片作为背景；必须支持用户自定义背景图片，并可恢复默认雪山背景。
- **导航按钮采用 Notion 式低圆角扁平导航（Subtle Rounded Sidebar Navigation）**：桌面端圆角建议 6px，单项高度建议 38px；使用紧凑、平直的整行导航项，不做胶囊形或大圆角卡片。
- 导航项默认背景透明、无边框、无阴影；Hover 时出现浅灰色半透明背景，选中时使用略深的低对比度灰色实色背景，避免大面积高饱和色块。导航项之间不加明显分隔线。
- 整行均为点击区域，图标和文字垂直居中；图标与文字间距紧凑，左右内边距约 12px。图标保持简洁统一，不使用过大的彩色图标。
- 展开箭头、添加、更多等辅助操作可在 Hover 时显现；辅助按钮不能挤压主导航文字，也不能改变导航行的整体高度。
- 该 Notion 式导航规范只约束侧栏导航控件，不限制主内容区继续使用精致卡片、圆角、阴影、渐变、半透明材质和动效。
- 左侧底部固定显示用户头像、用户名和个人菜单入口；点击头像或用户名打开菜单，集中提供账户/个人资料、设置、同步与存储、关于/诊断。设置与同步不得再作为左侧一级导航项。
- 背景图与导航文字之间必须保持足够对比度；必要时叠加渐变遮罩或半透明底层，不得牺牲可读性。

### 顶部搜索与同步状态

- 全局搜索支持书籍、作者、笔记、标签和可搜索的插件内容；点击进入全局搜索结果页，支持键盘快捷键。
- 右上角仅显示一个同步状态图标；同步成功时只显示「✓」，不显示「同步成功」、最近同步时间或其他文字。
- 同步中、失败、离线等状态使用对应的简洁图标区分；图标需有无障碍名称，悬停时可显示简短状态提示，但默认界面不出现状态文案。
- 同步设置、Provider 配置、同步历史和冲突处理统一从左下角「头像菜单 → 同步与存储」进入；右上角成功勾号只承担轻量状态提示。

### 首页内容模块与交互

| 模块 | 展示内容 | 点击行为 |
| --- | --- | --- |
| 欢迎区 | 欢迎语、用户名、简短阅读氛围文案；横向雪山背景 | 不作为主要操作区 |
| 继续阅读 | 当前书籍封面、书名、作者、可选摘录、阅读进度/章节、继续阅读按钮 | 继续阅读按钮进入 Reader 并恢复上次位置；封面/书名进入 Book Detail |

### 标签系统在首页的呈现

- 首页「我的标签」显示用户最近使用或手动置顶的标签；不把所有标签无上限铺开。
- 标签 Chip 显示名称与可选数量；标签颜色用于快速识别，需保证文字对比度。
- 点击标签进入统一标签结果页，可查看该标签关联的书籍和笔记，并按类型筛选。
- 「管理标签」进入标签管理页，支持创建、重命名、改色、合并、删除和置顶常用标签。

### 视觉与文字原则

- 以用户已通过的首页视觉稿为基准：左侧雪山、优雅 Granite 字体、浅紫/蓝灰色氛围、柔和的卡片层次、半透明表面和精致阴影。
- 卡片、圆角、阴影、渐变、毛玻璃和动效均可使用；应形成统一的视觉材质语言，不限制视觉表现力。
- 极简重点是去除无意义小字、冗余副标题、装饰性标签和重复解释；书名、作者、阅读进度、统计值等有用信息应清楚、易读。
- 首页各模块应有明显主次，不要求所有卡片同尺寸；继续阅读和最近阅读优先，统计、目标和标签作为次级信息区。
- 左侧默认雪山背景可更换；首页欢迎区背景与侧栏背景可作为独立设置项，默认可使用同一视觉主题。

### 页面状态

- 空书库：展示导入书籍入口和简洁引导，不显示虚构统计数据。
- 无继续阅读：将继续阅读模块替换为最近添加/推荐从书架选择一本书。
- 无笔记：提供新建笔记入口。
- 无标签：提供创建标签/从书籍添加标签入口。
- 同步失败/离线：右上角以简洁异常图标提示；用户可从「头像菜单 → 同步与存储」查看原因、重试和同步历史。
- 初次使用：允许用户跳过目标配置和标签整理，首页仍保持完整、可用。

### 验收标准

- 桌面横屏下左侧导航只包含主页、可展开书架、笔记、统计四项；设置与同步统一从左下角头像菜单进入，插件中心从「头像菜单 → 设置」进入。
- 书架展开/收起状态可保持；五个状态子项能正确筛选书籍。
- 左下角显示头像与用户名；左上角无独立 Logo 图标；Granite 品牌字样字体符合展示字体方向。
- 默认雪山背景可自定义并可恢复默认；更换背景后导航文字仍清晰。
- 右上角同步成功时只显示一个「✓」，不显示状态文字或相对时间；同步中/失败/离线状态使用简洁图标且可通过无障碍名称或悬停提示识别。
- 所有首页模块的跳转、返回和状态保持正确；标签入口能进入全局标签结果。
- 首页视觉实现必须基于真实运行截图验收，不以静态图或组件代码代替。

默认建议：书架中点击书籍条目进入 Book Detail；详情页的明确「阅读/继续阅读」操作进入 Reader。所有页面只能有一个清晰的主要操作层级，次要操作放在工具栏、上下文菜单或溢出菜单中。若实现选择不同的点击语义，必须在 Design Brief 和页面规格中统一说明，不得在不同列表中随机变化。

## 5. 导航、返回与状态保持

- 为所有 Core 页面定义稳定、可测试的 route ID；插件页面使用插件命名空间，例如 `plugin:<plugin-id>/<route-id>`，不得占用 Core route。
- Android 使用系统返回语义：优先关闭最上层弹窗/Sheet，再退出临时选择或搜索状态，再退出全屏阅读，最后按导航返回栈返回上一页面。不得无故直接跳首页或丢弃上下文。
- 桌面端支持侧栏导航、浏览器式返回/前进（若平台输入可用）、键盘快捷键和可见的当前目的地；窗口关闭与页面返回不能混为一谈。
- Reader 从 Book Detail、首页或搜索结果进入时，退出后恢复原入口上下文；阅读位置由 ReaderLocation 持久化。沉浸式模式隐藏应用主导航，但不改变导航栈。
- 搜索关闭或返回时保留搜索词、筛选条件和结果滚动位置；从结果打开对象后返回仍回到原结果集。
- 屏幕旋转、分屏、窗口缩放或导航容器变化时，不重置 route、返回栈、阅读锚点、列表滚动位置、筛选、搜索和未提交编辑；详见 Android 自适应布局约束。
- 只有存在真实数据丢失风险时才要求确认；无损的普通页面跳转不应反复弹出确认框。编辑内容应有明确的自动保存/手动保存状态。

## 6. 响应式导航与多栏布局

**[确定]** 沿用本规格书「五、可定制 UI」中的 Android 导航决定：竖屏使用底部 Navigation Bar，横屏使用左侧 Navigation Rail，平板/大屏使用适合窗口宽度的侧边导航；Windows 使用适合鼠标键盘和可调整窗口的侧栏/工具栏。两个平台共享目的地 ID 与页面结构，不强制像素级相同。

- 布局优先依据可用窗口宽度和 Window Size Classes，而非只根据设备型号或横竖屏判断。
- Compact：以单栏、全屏子页面和 Sheet 为主；列表到详情采用页面跳转。
- Medium / Expanded：可使用列表 + 详情、笔记列表 + 编辑器、设置分类 + 内容面板等主从双栏；空间足够时才展示第三栏。
- 桌面窗口缩窄时应退化为可用的单栏或 Rail 布局；窗口扩大时再恢复多栏，且保留当前选择和滚动状态。
- Reader 是沉浸式例外：默认隐藏全局导航；目录、标注、笔记等工具以临时面板或 Sheet 呈现，关闭后回到正文原位置。
- 不把手机页面简单拉宽铺满平板；需要重新分配导航、内容宽度、列数和同时可见的信息量。

## 7. 插件页面接入规则

- 插件可注册二级页面、可选一级目的地、Dashboard Widget、Reader 面板、工具栏动作、上下文菜单和插件设置页。
- 插件贡献必须声明唯一 ID、标题、图标、平台兼容性、所需权限、显示条件、排序建议和可用尺寸；插件页面使用命名空间路由。
- 插件一级目的地默认不自动挤占 Core 导航；先放入「更多」或插件中心，用户可固定、隐藏和排序。空间不足时收纳到「更多」。
- 插件卸载/禁用后隐藏其入口，但保留用户数据；缺失插件不得导致页面崩溃、Core route 失效或其他插件无法启动。
- 插件不能覆盖系统返回、核心 Reader 手势、无障碍操作或 Core 页面；布局定制必须通过受控 Slot / Token API。

## 8. 每个页面的设计与交付模板

新增或重做任何页面前，必须提交页面规格，至少包含：

1. 页面 ID、名称、所属导航层级、进入来源、返回目标。

4. 加载、空、离线、错误、权限不足、只读、选中、编辑中、保存成功/失败等适用状态。

6. 键盘、鼠标、触控、系统返回、焦点顺序、屏幕阅读器和大字体行为。
7. 可扩展 Slot、插件权限与插件缺失时的降级行为。
8. 关键跳转的来源/目标、状态保留策略和返回路径。
9. 真实运行截图与验收记录，不得只提交静态 HTML 或组件代码。
10. 首版必须组件清单：列出页面所有基础组件、可见操作、数据依赖、插件依赖与不适用项；不得遗漏 Reader、书架、详情、Notebook、统计、设置和同步的基础能力。
11. 验收用例：为每项首版必须功能写出可重复的成功、空、错误、离线/权限和恢复测试；注明测试数据、平台、结果和证据。
12. 需求追踪：建立「规格条目 → 页面/组件 → 测试用例 → 验收结果」映射；没有验证证据的功能不能标记完成。

## 9. 必须遵循的 UI 设计参考

**[确定] Reeden 是 Reader 的首要产品与视觉设计参考。** 所有产品级 UI 设计、实现和视觉审查必须研究并参考 [Reeden 官方产品](https://reeden.app/cn) 及其官方文档。具体可借鉴模式、采用边界和研究链接见本规格书「六-B、Reeden 产品参考与可借鉴模式」。

- 设计书架时参考 Reeden 的 [书架外观](https://docs.reeden.app/bookshelf_layout)：封面网格与信息列表、搜索和快速筛选、封面呈现与内容层次。
- 设计导航和跨屏布局时参考 [应用外观](https://docs.reeden.app/app_appearance)：手机底部导航、大屏侧边栏、可折叠导航与自定义目的地。
- 设计阅读器时参考 Reeden 的阅读工作区、浮动工具栏、目录/侧边面板和沉浸式阅读方式；具体实现仍须遵守本项目已确定的 PDF 二维自由画布手势。
- 设计主题时参考 [应用主题](https://docs.reeden.app/app_theme) 与 [主题和背景](https://docs.reeden.app/theme_background)，保持应用主题与阅读主题可以独立设置，并提供直观预览。
- Reeden 是产品与视觉模式参考，不是逐像素复刻目标；不得复制其品牌资产、专有图标、截图、具体文案或受版权保护的资源。
- **不使用 Material Design 3 / M3 Expressive 作为设计系统要求。** 不要求 Agent 加载 Incredible MD3 in GPT Skill，不要求采用 MD3 Token、组件、颜色角色或 Expressive 视觉规范。Android 仍应遵循操作系统的导航、系统返回、安全区、无障碍和窗口行为，这些平台约定不等于采用 MD3 作为整体设计系统。
- **极简原则约束信息噪声，不限制视觉表现力。** 禁止没有信息价值的微小文字、装饰性小标签、重复解释、冗余副标题和密集脚注；每条文字都应帮助识别、理解、决策或操作，字号必须保证实际可读。卡片、圆角、阴影、渐变、半透明/玻璃材质、光效、动画和转场均允许使用，也欢迎精致、丰富、有层次的高端视觉表现；根据品牌气质、信息分组、空间层次和交互反馈有意识地设计，不设一刀切禁令。避免随机装饰和所有内容机械套用同一种卡片模板。
- 实施前先理解用户任务和现有代码，再写简短 Design Brief，说明视觉主张、颜色角色、字体层级、信息密度、布局、表面、形状、动效与 Light/Dark 策略；不得套用通用 Dashboard 模板。
- 真实运行应用并检查截图，覆盖手机竖屏/横屏、平板、桌面窗口、Light/Dark、大字体、真实书籍内容、空/加载/离线/错误状态。修复后重新运行和截图；没有真实运行检查记录时，不得宣称视觉验收通过。
- 页面局部设计与 Reeden 参考、Reader 自有视觉 Token 或已确认的平台行为冲突时，以产品任务、用户明确决定和本规格书的已确认约束为准，并记录设计决策。

## 10. 信息架构验收标准

- 页面树中的每个 Core 页面都有唯一 route ID、明确入口、返回目标和权限边界；不存在无法到达的孤立页面。
- 每个可见按钮、图标按钮、菜单项和 Widget 都有明确动作、状态反馈、失败处理和无障碍名称；不允许无动作的装饰性控件。
- 一级导航目的地数量受控；同级页面用 Tabs，跨任务区域用主导航，复杂编辑使用独立页面，短决策使用 Dialog，依赖上下文的短流程使用 Sheet。
- 从首页、书架、搜索、书籍详情进入 Reader/Notebook 的跳转均可返回原上下文；返回行为在 Android、桌面端一致可预测。
- Android 旋转/分屏、桌面窗口缩放、主题切换和插件启停不造成页面丢失、导航重置或数据丢失。
- 插件未安装、禁用或崩溃时 Core 页面仍可正常使用，插件入口和数据按契约降级。
- 关键页面状态、不同窗口尺寸和 Light/Dark 的真实截图通过 Visual Review；问题修复后复查。

## 10-A. 首版页面交付与验收基线（Core Release Gate）

本节将页面树中的首版页面转化为可执行的交付清单。页面完成必须同时满足「页面可用、组件齐全、关键流程闭环、状态完整、数据可恢复、适用的自动化检查通过」；真机与真实云端验收按当前交付范围更正交由用户手测。只完成静态布局、主流程演示或正文渲染，不算页面完成。下列标为「首版必须」的项目不能以未来迭代为由省略；确实不适用的项目必须注明原因和替代行为。

### 10-A.1 全局应用框架与共享组件

- **应用框架**：品牌区、一级导航、当前页面状态、头像菜单、全局搜索入口和同步状态入口在所有平台可达；桌面端与 Android 按可用窗口尺寸使用正确导航容器。
- **导航组件**：支持选中态、展开/收起、返回栈、来源上下文恢复、键盘焦点和无障碍名称；旋转、分屏、窗口缩放或切换导航容器时不丢失当前页面与状态。
- **列表/网格组件**：支持加载、空数据、错误、刷新、排序、筛选、选中、多选、批量操作和长列表滚动；书籍封面比例正确，缺失封面有统一占位。
- **搜索组件**：支持输入、清空、提交、取消、历史/最近搜索（若启用）、键盘快捷键、无结果、错误和加载状态；搜索结果能回到原始对象。
- **元数据组件**：书名、作者、文件格式、文件大小、阅读状态、进度、标签、集合和更新时间有一致的显示与编辑方式；缺失字段不显示伪造值。
- **表单组件**：文本输入、选择器、开关、文件夹/文件选择、验证错误、保存状态和恢复默认值均有明确反馈；失败时保留已输入内容。
- **操作组件**：工具栏、图标按钮、溢出菜单、上下文菜单、Dialog、Sheet、Toast/状态提示、进度指示和确认流程都有明确动作；危险操作说明影响范围并提供可恢复路径。
- **通用页面状态**：所有适用页面至少覆盖首次加载/骨架屏、空状态、正常状态、加载更多、离线、错误/重试、权限不足、只读、保存中/成功/失败、选择/编辑中和长内容状态。
- **无障碍与输入**：可见控件有可访问名称和状态；支持键盘焦点顺序、大字体/缩放、触控目标、屏幕阅读器和系统返回；不能只靠颜色表达状态。
- **统一反馈**：用户操作后能看到结果；失败时给出可理解原因、重试或恢复入口；禁止没有动作的按钮、假进度、吞掉错误或静默丢数据。

### 10-A.2 页面级首版验收清单

#### 1. 首页（Home）

沿用本页「首页（Home / Dashboard）」中的独立布局、内容模块和验收标准。首版至少验证继续阅读恢复位置、最近阅读/最近笔记跳转、统计摘要进入对应统计页、今日目标状态、标签入口和自定义背景；空书库、无笔记、无标签、同步失败/离线均有完整状态。

#### 2. 书架（Bookshelf）

- 有网格/列表两种浏览方式；书籍封面、书名、作者、阅读状态和进度信息层级清晰，缺失封面/元数据有占位。
- 支持按书名/作者搜索，按阅读状态、集合、标签、来源文件夹筛选；支持排序、清除筛选和查看当前筛选条件。
- 支持全部、阅读中、未读、已读、收藏等固定入口；从入口进入后筛选条件正确，返回时保留原列表位置。
- 支持创建/管理集合、标签和来源文件夹；支持单本与多选批量编辑元数据、标签、集合、状态及适用的删除/导出操作。
- 支持单文件/批量导入入口、拖拽和 Android 系统分享；支持重复检测、缺失文件提示、重新定位文件和导出。
- 删除书籍时明确区分 Granite 管理的文件与外部关联原文件，遵循「删除书籍」与「解除目录关联」的既定数据安全规则。
- 验收：网格/列表切换、搜索筛选组合、多选批量操作、重复导入、缺失文件重定位、空书架、长列表和返回状态均通过真实数据测试。

#### 3. 书籍详情（Book Detail）

- 展示封面、书名、作者/译者、出版社、ISBN/DOI、系列、语言、出版时间、格式、大小、来源文件和可用的其他元数据；缺失字段不占用无意义空位。
- 展示阅读状态、整体进度、最近阅读位置；提供清晰的「阅读/继续阅读」主要操作，并恢复上次位置。
- 提供编辑元数据、封面、标签、集合和阅读状态的入口；保存后书架、首页和搜索结果同步更新。
- 能查看本书书签、高亮、批注和关联 Notebook 笔记，并可跳转到对应阅读位置/笔记。
- 提供文件定位、重新关联/重定位和文件信息查看；文件缺失时有明确错误与修复入口。
- 删除/移出书库操作清楚区分删除 Granite 管理的文件、解除外部文件关联和删除云端对象；执行前展示影响范围。
- 验收：从书架、首页、搜索和 Notebook 关联入口进入详情均正确；编辑后数据一致；继续阅读恢复位置；文件丢失、只读和删除确认流程通过测试。

#### 4. Reader（阅读器）

必须通过「Reader Core 首版组件基线与格式验收」中 A–F 全部适用项目。任何一种首版格式不能只提供正文打开能力；目录、搜索、进度、书签、阅读外观、位置恢复、适用的文本选择与标注、错误处理和沉浸式体验均须逐项验收。

#### 5. Notebook

- 提供笔记浏览器：文件夹树、笔记列表、搜索、标签筛选、新建、重命名、移动和删除；支持从书籍或选中文字创建笔记。
- 编辑器提供 Markdown 源码编辑与预览；至少支持标题、段落、粗体/斜体、列表、任务列表、引用、代码、链接和图片/附件引用等常见 Markdown 内容。
- 编辑中支持撤销/重做、保存状态、自动保存或明确的手动保存；关闭、切换笔记、应用重启和离线状态下不丢失已确认保存的内容。
- 支持 WikiLink、反向链接、标签、书籍关联、引用文本和 ReaderLocation；点击引用可跳回原书对应位置，书籍关联笔记可从书籍详情进入。
- 支持附件添加/预览/打开、相对路径迁移、模板、全文搜索和 Markdown 导入/导出；知识图谱仍为可选 UI 插件。
- 同步冲突不能静默覆盖整篇笔记；必须展示冲突状态并提供恢复/冲突副本等安全处理。
- 验收：新建/编辑/预览/重命名/移动/删除、双链更新、反向链接、附件迁移、书籍引用跳转、离线编辑、冲突恢复和 Markdown 往返导入导出均通过测试。

#### 6. 阅读统计（Statistics）

- 提供日/周/月/年时间范围切换；展示阅读时长、阅读日历/热力图、连续阅读天数、阅读会话趋势、书籍进度/完成情况和目标进度。
- 支持按日期查看会话，按书籍查看进度/阅读记录；图表和摘要可下钻到对应数据，不展示无法解释的数据。
- 目标可查看、设置和调整；目标变化后统计页面即时反映。
- 统计来自原始 Reading Session，可重新计算；后台、锁屏和长时间空闲不计入有效阅读时长；跨设备会话按唯一 ID 去重。
- 支持无阅读记录、部分数据、跨时区/跨日、会话被中断和手动修正后的状态。
- 验收：使用已知时间戳和会话样例核对日/周/月/年汇总、时区边界、空闲暂停、跨设备去重、目标完成率和下钻结果。

#### 7. 全局搜索（Global Search）

- 搜索书籍标题、作者、元数据、Notebook 笔记、标签及已声明可搜索的插件内容；结果按对象类型分组。
- 支持键盘快捷键、输入/清空、结果筛选、无结果、加载、错误和取消；选择结果进入对应详情/阅读器/笔记。
- 从结果进入对象后返回，保留搜索词、筛选条件、结果集和滚动位置；结果显示足够的上下文以区分同名对象。
- 验收：跨类型检索、组合筛选、重复名称、无结果、离线/索引更新和返回状态通过测试。

#### 8. 导入向导（Import Wizard）

- 支持单文件、批量文件、桌面拖拽、系统文件选择器和 Android 分享入口；导入前显示目标书库。
- 展示解析进度、格式识别、元数据提取、封面、重复检测和必要的元数据确认；允许用户修正错误字段。
- 支持选择导入目标、跳过/替换/保留重复项等明确策略；不得静默覆盖已有书籍或文件。
- 展示逐文件进度、成功/失败/跳过结果；失败项可重试，其他成功文件不重复导入。
- 验收：四种首版格式、批量混合格式、重复文件、损坏文件、取消导入、磁盘不足和部分失败均有正确结果报告。

#### 9. 设置（Settings）

- 通用：语言、启动/行为等已纳入规格的基础选项有当前值、保存状态和恢复默认值。
- 外观与布局：应用主题 Light/Dark、布局密度、导航/背景等已定义选项可预览、应用并持久化；阅读主题与应用主题独立。
- 书库与文件夹：查看/选择/添加/移除本地书库根目录；支持多根目录、权限重新授权、目录迁移、不可用目录恢复；解除关联不误删文件。
- 阅读器：全局默认字体、字号、行距、边距、阅读模式、主题和输入/手势设置可配置；单本覆盖项与全局默认项关系清晰。
- 快捷键与输入：展示快捷键、允许修改/恢复默认，冲突时提示；系统保留快捷键优先级。
- 数据与备份：完整导出/导入、备份恢复、版本兼容、进度和错误报告；凭证不默认导出。
- 插件权限与管理入口能跳转到插件中心；每项设置变更后立即反馈并在重启后保持。
- 验收：每个可见设置项至少验证默认值、修改、持久化、恢复默认、非法值和失败反馈；不允许出现未实现但可交互的占位设置。

#### 10. 同步与存储（Sync & Storage）

- 能添加、编辑、验证和移除 Local Filesystem、S3-compatible、WebDAV Provider；配置失败时保留输入并显示可理解原因。
- 展示当前 Provider、连接状态、同步策略、队列、进度、最近同步结果、历史记录和失败原因；支持手动重试/取消。
- 支持全量、仅元数据、指定集合/书籍、元数据优先并按需下载四种策略；策略切换不误删云端文件或误判未下载文件。
- 书籍文件与同步元数据必须绑定同一个 Provider Profile；界面不得允许配置成混合 Provider。
- 冲突入口展示对象、设备/版本来源和处理结果；用户确认前不静默覆盖。Token 失效、网络断开、限流、空间不足和远端损坏均有恢复路径。
- 验收：首次连接、凭证错误、离线、恢复同步、重复同步、并发修改、删除传播、策略切换、断点续传、Hash 校验和冲突恢复通过测试。

#### 11. 插件中心（Plugin Center）

- 分开展示可发现插件、已安装插件、更新和插件详情；详情显示名称、版本、作者、来源、许可证、兼容性、依赖、权限和数据影响。
- 支持安装、权限确认、启用、禁用、更新、卸载和失败恢复；更新失败可回滚到可用版本或恢复原状态。
- 权限申请按能力逐项说明；撤销权限后插件不能继续访问已撤销能力。
- 缺失依赖、循环依赖、版本不兼容、来源/完整性校验失败和插件崩溃均有明确提示与隔离行为。
- 插件提供的页面/面板/工具栏/Widget 按声明 Slot 接入；插件禁用/卸载后 Core 页面、数据和导航状态不损坏。
- 验收：本地包、第三方来源、权限拒绝/撤销、安装失败、升级、降级/回滚、卸载清理、崩溃隔离和无插件运行通过测试。

#### 12. 标签管理与标签结果页

- 标签管理支持创建、重命名、改色、置顶、合并和删除；合并迁移全部关联，删除标签不删除书籍/笔记。
- 标签结果页统一展示关联书籍和笔记；支持对象类型、书籍状态、最近修改时间筛选和打开对象。
- 多标签筛选支持匹配任意/全部；书架与 Notebook 的筛选结果一致。
- 验收：跨对象关联、重命名、合并、删除、批量应用/移除、导入去重、离线修改和同步通过测试。

#### 13. 头像菜单、账户与诊断

- 头像菜单至少能进入账户/个人资料、设置、同步与存储、关于/诊断；菜单在桌面与 Android 的入口符合各自布局。
- 诊断信息可查看应用版本、平台、Provider/插件状态和错误日志；日志脱敏，不默认上传书籍内容、笔记正文、凭证或隐私数据。
- 诊断包由用户主动导出；导出前说明包含内容和保存位置。
- 验收：菜单入口可达、页面返回正确、日志脱敏、诊断包导出与权限拒绝状态通过测试。

#### 14. 冲突处理与其他关键流程页

- 冲突处理页必须展示冲突对象、冲突字段/版本、来源设备、时间和可选解决方式；在用户确认前保留两侧数据。
- Provider 配置、插件安装、批量导入、书籍编辑等流程必须有步骤状态、取消、失败恢复和完成结果；中断后不留下半完成的数据库/文件状态。
- 验收：并发修改、取消流程、进程中断、重试、重复提交和恢复后数据一致性通过测试。

# 六、阅读器与书库

**[确定]** 首版 Core 原生支持 EPUB、PDF、TXT、MOBI 四种格式。AZW3、CBZ/CBR 不属于首版 Core 必须内置的格式，可由 Format 插件扩展。Format 插件可注册格式识别、解析、阅读视图、元数据提取、封面提取和导入导出能力。**[建议]** EPUB 评估 Foliate.js，PDF 评估 PDFium、MuPDF 等；最终选择需审查体积、Android 支持、文字选择/标注和许可证。

书库能力：本地文件导入、批量导入、拖拽/Android 分享、封面、作者/译者/出版社、ISBN/DOI、系列、语言、出版时间、文件格式与大小、标签、集合、阅读状态、排序筛选、搜索、批量编辑、重复检测、文件丢失重定位、元数据补全、备份与导出。

## 标签系统（跨书籍与 Notebook）

**[确定]** Granite 必须提供跨书籍与 Notebook 的统一标签系统；标签是 Core 级数据能力，不依赖某个插件才能创建、查看或筛选。

- 同一个标签可以同时关联多本书和多篇笔记；一本书/一篇笔记可以拥有多个标签。
- 标签使用稳定 tagId；至少包含名称、可选颜色、创建/修改时间和对象关联。标签名称可重命名，重命名不改变 tagId 和既有关系。
- 首版采用扁平标签集合；支持搜索、按名称排序、最近使用、常用/置顶标签。层级标签/嵌套标签作为未来可选扩展，不作为首版前置条件。
- 支持创建、编辑名称、改色、置顶/取消置顶、合并重复标签和删除标签。合并时将所有关联迁移到目标标签；删除标签只移除标签及其关联，不删除书籍或笔记。
- 书架和 Notebook 均支持标签筛选；可同时选择多个标签，并与阅读状态、集合、文件夹、笔记文件夹和全文搜索组合筛选。提供「匹配任意标签 / 匹配全部标签」切换。
- 标签结果页是统一入口，显示关联书籍和笔记，并按对象类型、书籍状态、最近修改时间筛选；点击对象进入对应书籍详情或笔记。
- 首页「我的标签」展示最近使用或用户置顶的标签及关联数量；标签点击进入标签结果页；「管理标签」进入「头像菜单 → 设置 → 标签」。
- 标签与关联关系属于同步元数据，必须在设备间同步；切换同步模式时遵循用户选择的元数据同步策略。
- 标签支持批量应用/移除、导入/导出和重复检测。导入外部书库时应尽可能保留来源标签并提供映射/去重。
- 插件可读取标签；写入、批量修改或删除用户标签必须申请相应权限。插件自有标签可声明命名空间，不得与用户标签发生静默覆盖。
- 验收：在书籍上添加标签后，Notebook 和首页能检索到同一标签；多标签筛选结果准确；重命名/合并/删除后所有关联一致；离线修改后可正确同步。

书籍身份区分 bookId 与 SHA-256 内容 Hash；相同文件不同设备可通过 Hash 识别，但不同版本、同内容不同元数据不能无条件合并。

阅读器：目录、跳转、分页/滚动、字号/字体/行高/页边距、主题、沉浸式、书签、高亮、批注、选择文字、复制/分享、书内搜索、阅读位置自动保存、每本书独立设置、键盘快捷键和触控手势。PDF 的高亮、下划线、文本批注和墨迹标注必须支持直接写回 PDF 文件；标注保存后仍可在兼容 PDF 阅读器中查看。

## Reader Core 首版组件基线与格式验收

本节定义 Reader 首版必须交付的基础能力。Reader 页面不能只完成正文渲染和翻页；下列组件、操作和状态属于首版基础阅读体验。所有基础能力由 Host/Core 提供，不得要求用户先安装插件。某项能力受文件本身限制时，应明确显示不可用原因，不得留下无响应按钮。

### A. 所有格式共用的阅读器框架

- **阅读画布**：正文区域是视觉主体；支持连续滚动或分页阅读模式（由格式和用户设置决定），滚动位置与页面边界稳定，不出现正文被工具栏遮挡、横向意外溢出或切换模式后跳回开头。
- **顶部/浮动工具栏**：至少提供目录/章节导航（文件具备目录时）、书内搜索、书签、标注列表、阅读外观、阅读模式/布局、阅读进度，以及退出/返回。工具栏可自动隐藏；点击屏幕中央或使用明确的工具栏入口可重新显示。
- **阅读进度组件**：显示当前页码或章节位置及整体进度；可通过进度控件跳转。进度显示必须与实际阅读位置一致，不能只更新 UI 而不更新 ReaderLocation。
- **目录与章节导航**：展示目录层级、当前章节定位和章节跳转；目录不存在或文件不提供章节信息时，隐藏或明确禁用入口，不得展示空白面板或无效操作。
- **书内搜索组件**：输入关键词后显示匹配数量与上下文；支持上一个/下一个结果、结果定位与命中高亮、清空搜索和无结果状态。搜索过程可取消，搜索结果不能改变已保存的阅读位置，除非用户主动跳转。
- **书签组件**：可在当前位置新增/删除书签；可查看书签列表、跳转到书签位置、删除单个书签；书签在关闭重开和设备同步后仍存在。
- **标注列表与管理组件**：集中查看本书高亮、下划线、文本批注和适用格式的墨迹标注；支持按位置跳转、编辑备注/颜色和删除。删除或修改前有明确反馈，操作后正文与列表保持一致。
- **文本选择与上下文操作菜单**：选择文本后至少提供复制、分享、创建高亮、下划线、添加批注、创建关联 Notebook 笔记等适用操作；取消选择后恢复正常阅读手势。格式不支持文本选择时，应明确说明限制。
- **阅读外观面板**：至少能设置字体、字号、行距、段距、页边距、阅读宽度和阅读主题；设置即时预览，关闭重开后保留。应用主题与阅读主题分离，PDF 原始页面颜色默认不被阅读主题篡改。
- **阅读模式与布局控制**：EPUB/TXT/MOBI 等重排文本支持分页与连续滚动；PDF 按本规格定义的连续二维画布工作。格式不适用的模式不显示为可选项。
- **全屏/沉浸式控制**：进入和退出沉浸式阅读；工具栏自动隐藏/唤出；系统栏、系统返回和安全区域行为符合平台规则；退出后恢复应用导航。
- **阅读位置自动保存与恢复**：打开时恢复上次位置；翻页、滚动、章节跳转和关闭时可靠保存；进程异常退出后恢复到最近有效位置。保存频率需避免每帧写库，同时不能因快速退出丢失明显进度。
- **每本书独立设置**：允许单本书覆盖默认阅读主题、字体、字号、行距、边距、分页/滚动模式和适用的手势配置；恢复默认只影响该书的覆盖项，不破坏全局设置。
- **跨平台输入**：桌面支持鼠标、触控板、键盘和可配置快捷键；Android 支持触控与系统返回。所有输入调用统一 Reader Navigation/Input API，不能出现不同控件各自修改阅读位置的情况。
- **阅读状态反馈**：覆盖加载中、渲染中、字体/资源加载失败、文件损坏或不支持、离线、只读、保存中、保存失败、标注写回中/失败等状态；失败后保留用户可恢复的数据。
- **插件缺失降级**：不安装主题、手势或工具栏插件时，目录、搜索、书签、标注、阅读外观、进度保存和沉浸式阅读仍然可用。

### B. EPUB 首版验收

- 能解析并显示 EPUB 正文、章节结构、目录、书名/作者等可读取元数据；章节跳转和正文链接可用。
- 支持文字重排；更改字体、字号、行距、段距、边距、阅读宽度和主题后，正文重新排版且不丢失当前章节附近的阅读位置。
- 支持分页与连续滚动；切换模式后保持同一段落/章节锚点附近，不回到书首。
- 支持书内搜索、文本选择、复制/分享、书签、高亮、下划线、文本批注和创建 Notebook 笔记；标注可从列表跳回原文位置。
- EPUB 标注保存在 Granite 的可迁移数据中，并通过稳定文本引用与 EPUB CFI/位置锚点定位；重新打开、同步和重新排版后仍可定位。定位失效时显示待修复状态，不得静默丢弃。
- 图片、脚注、超链接、列表、表格和常见章节排版可正常呈现；超长章节、缺失字体或损坏资源有明确降级反馈。
- 关闭并重新打开、切换设备或更换阅读模式后，恢复正确章节、段落和进度。

### C. PDF 首版验收

- 按文档顺序纵向连续排列所有页面，形成统一二维画布；支持 Fit Width 初始显示、连续缩放和自由平移。可提供适合页面/实际大小等常用缩放预设，但不得破坏自由画布语义。
- 严格遵循「Android：PDF 二维自由画布」中单指/双指 X/Y 平移、双指中心点缩放、边界过拖与回弹、系统返回优先级和长文档懒加载要求；桌面端滚轮、触控板和键盘行为也必须通过测试。
- 显示当前页码/总页数；可输入页码跳转；PDF 内嵌目录存在时可按目录跳转；支持书内全文搜索与结果定位。
- 支持可提取文本的选择、复制/分享、搜索命中定位和上下文菜单；扫描型 PDF 无文本层时，应明确提示文本选择/搜索受限，不得伪装成可用。
- 至少支持高亮、下划线、文本批注和墨迹注释。标注必须写回 PDF 本身，关闭并重新打开后仍存在，并可在至少一种外部兼容 PDF 阅读器中读取；不能只写入 Granite 私有数据库或旁路文件。
- 标注写回采用安全保存：原文件备份/可恢复版本、结果校验、Hash 更新、同步队列更新；中断、磁盘不足、文件只读和同步冲突均可恢复。
- 书签、标注列表、阅读位置、缩放比例和二维视口位置在退出、重进、旋转和窗口变化后恢复；无法精确恢复时至少回到同一页附近。
- 长文档按视口懒加载/分块渲染；快速滚动、缩放和跨页时不出现持续空白页、明显模糊、页面错位或不可接受的内存峰值。

### D. TXT 首版验收

- 能识别并显示纯文本内容；自动识别常见编码，无法可靠识别时允许用户选择编码并预览，避免乱码后直接导入。
- 支持自动换行、字体/字号、行距、阅读宽度、主题、分页/连续滚动和阅读位置恢复；长文本不能因单次加载全部内容而卡死。
- 支持书内搜索、结果前后跳转、文本选择、复制/分享、书签、高亮、下划线、文本批注和创建 Notebook 笔记。
- TXT 标注保存在 Granite 可迁移数据中，使用文本引用与稳定位置锚点；内容变化或编码变化导致定位失效时提供修复提示。
- 空文件、超大文件、异常编码和无法读取文件均有明确状态与恢复入口。

### E. MOBI 首版验收

- 能识别并打开首版声明支持的 MOBI 文件，提取可用的书名、作者、目录和正文；文件变体或资源无法解析时给出具体错误，不得静默显示空白页。
- 支持文本重排、分页/连续滚动、字体/字号/行距/段距/边距/主题、目录跳转、书内搜索和阅读位置恢复。
- 支持文本选择、复制/分享、书签、高亮、下划线、文本批注和创建 Notebook 笔记；标注保存在 Granite 可迁移数据中并使用格式适配的稳定位置锚点。
- 重新打开、切换设备和修改阅读外观后，目录、正文、标注和阅读位置保持一致。

### F. Reader 基本验收

- 使用真实 EPUB、PDF、TXT、MOBI 文件，确认四种格式均能导入并打开阅读。
- 检查目录或页码跳转、搜索、书签和阅读位置保存；关闭应用后重新打开，阅读位置仍能恢复。
- 检查常见文件错误时有清楚提示，不出现无响应或应用崩溃。
- PDF 高亮、下划线、文本批注和墨迹标注写回原文件，并使用其他 PDF 阅读器确认结果。
- 基本阅读能力由自动化检查覆盖；真实 Windows 与 Android 应用检查由用户后续手测，本次不执行。Android 禁止使用任何模拟器或虚拟设备。
- 不建立复杂的格式兼容性测试矩阵；暂不支持的格式变体在文档中说明即可。

### H. Reader 常用控件补充验收

- PDF 工具栏至少提供 Fit Width、Fit Page、Actual Size、放大/缩小、页码输入跳转和旋转页面（按 90° 旋转）；旋转仅改变阅读视图时不得意外改写原始 PDF 页面，若支持永久旋转则必须单独确认。
- PDF 当前页/总页数、缩放比例和目录/缩略图入口（文件存在相应结构时）保持同步；从搜索结果、目录、书签或缩略图跳转后，页码与画布位置一致。
- EPUB/TXT/MOBI 的章节导航应显示当前位置；章节跳转、脚注/内部链接跳转后提供可预测的返回原阅读位置行为。
- 文本选择菜单中的高亮颜色、下划线、批注、复制、分享和创建笔记均需有明确可见反馈；取消选择、关闭菜单或执行失败后恢复正常阅读交互。
- 阅读器设置面板应区分全局默认值与当前书籍覆盖值，并能一键恢复当前书籍默认值；不得误改其他书籍。
- 阅读器工具栏在紧凑屏幕下不得遮挡正文或将基础操作隐藏到无法发现的位置；常用操作可达，次要操作可收纳到明确的更多菜单。

定义格式无关 ReaderLocation，保留 EPUB CFI 或 PDF 页码/坐标等格式特定字段；标注包括 annotationId、bookId、类型、文本引用、定位、颜色、备注、创建修改时间和版本。换书籍版本时检测失效定位并支持修复。

## PDF 标注与直接写回

**[确定]** PDF 标注不能只保存在 Granite 私有数据库或旁路文件中；用户执行保存后，标注必须写入对应 PDF 文件本身，形成可由其他兼容 PDF 阅读器读取的标准 PDF 注释。应尽可能保留注释的可编辑性，不默认扁平化到页面图像。写回操作需采用安全保存流程：保留原文件备份/可恢复版本、校验写回结果、处理中断与磁盘空间不足，并在写回完成后更新文件 Hash 和同步队列。标注类型至少覆盖高亮、下划线、文本批注和墨迹注释。是否必须支持主动识别并优化 S Pen / Surface Pen 等触控笔输入，仍待确认；普通触控/鼠标输入不能因此受限。

# 六-A、阅读交互、手势与沉浸式模式

## 产品体验目标

阅读器必须优先保证阅读内容本身，阅读界面不应看起来像后台管理 Dashboard。视觉设计需有完整的排版层级、克制的控件、稳定的留白和一致的设计 Token；书架、笔记和设置可以使用应用导航，但阅读页面应减少持续可见的非阅读 UI。HTML 原型仅用于验证页面关系和交互，不作为最终视觉质量基准。

## 桌面端鼠标与触控板

Windows 必须原生支持鼠标滚轮、触控板和键盘阅读操作：

- 连续滚动模式：垂直滚轮滚动正文，触控板双指滚动正文。
- 分页模式：垂直滚轮按配置切换上一页/下一页；滚轮方向、灵敏度、累计阈值和翻页动画可配置，避免轻微滚动连续跳多页。
- 水平触控板手势可按配置翻页；Shift + 滚轮可作为可选水平滚动/翻页映射。
- 鼠标侧键（浏览器式 Back/Forward）可映射上一页/下一页；必须可禁用，避免与系统导航冲突。
- 键盘支持方向键、空格、PageUp、PageDown、Home、End 等可配置快捷键。
- 所有翻页手段应调用统一 Reader Navigation API，不应由不同 UI 组件分别修改阅读位置。

## Android 触控

### PDF：二维自由画布（Free Pan & Zoom Canvas）

PDF 的全部页面按文档顺序纵向连续排列，组成一个整体的长文档画布。页面之间保持固定的文档布局关系；用户操作的是整张画布，而不是单独翻页或切换页面。

- **单指拖动始终是二维平移**：任何缩放比例下，单指都可以沿 X / Y 任意方向拖动画布。不得把单指手势锁定为纵向滚动、横向翻页，也不得根据当前缩放比例切换单指手势语义。
- **双指拖动同样可以二维平移**：双指中心点的移动量平移整张画布；两指距离变化额外执行连续缩放。平移与缩放可以在同一手势过程中同时发生。
- **捏合缩放**：以双指中心点作为缩放锚点，尽量保持锚点下的 PDF 内容在屏幕中的位置稳定；缩放连续，不依赖离散档位。缩放和平移使用同一个文档视口变换。
- 初始缩放默认 Fit Width（页面宽度适配视口宽度）；全部页面仍是一个连续画布。Fit Width 只是初始比例，不改变单指/双指的自由平移语义。
- **水平拖动边界与回弹**：允许用户暂时拖出页面边缘并露出空白，但空白最多占视口宽度的 50%。在 Fit Width 时，水平拖动最多暂时露出半个视口宽度的空白；松手后以弹性动画回到页面恰好填满视口的对齐位置（水平偏移归零），不得回到画布中心或居中缩放。放大状态下，页面内容覆盖视口的合法平移范围内可自由停留；越过内容边界时允许最多 50% 视口宽度的弹性过拖，松手后回弹到最近的内容边缘对齐位置。
- **垂直移动**：单指或双指均可沿垂直方向自由拖动画布；文档连续移动，不按页吸附、不强制逐页翻动。松手后的惯性滚动自然衰减；仅在整份文档的顶部/底部边界执行弹性回弹，不把视口拉回文档中心。
- 手势识别不得进行强制 X/Y 方向锁定。系统边缘返回手势优先级高于阅读器画布拖动，阅读器不得拦截系统返回。
- 长按可进入 PDF 文本选择；文本选择状态下按系统/平台惯例显示选择句柄和操作菜单。普通拖动默认操纵画布，不以文本选择抢占单指拖动。
- PDF 页面按视口懒加载/分块渲染；缩放后按需提升渲染分辨率，不得将整份长 PDF 一次性栅格化到内存。
- 旋转屏幕、窗口尺寸变化、临时离开再返回时，尽可能恢复当前文档锚点、缩放比例和视口位置；若布局变化导致无法精确恢复，至少恢复到同一页附近。
- PDF 在 Android 上默认使用该二维连续画布模型；不提供左右滑动翻页作为默认 PDF 手势。

### 其他触控行为

- 点击屏幕中央：显示或隐藏阅读工具栏与阅读状态信息。
- EPUB 的分页/连续滚动及触摸翻页行为独立定义，不得套用 PDF 的画布手势规则。
- 系统返回手势必须保持可用；阅读器不得吞掉系统边缘返回手势。
- 手势需要清晰的触摸反馈、可访问性替代操作和冲突仲裁；不得为了识别方向而强制锁定 PDF 画布的 X/Y 轴。

## 全屏与沉浸式阅读

- Android 阅读器必须支持沉浸式全屏，默认进入阅读时隐藏应用内顶部/底部导航和非必要工具栏。
- 适用时使用 Android edge-to-edge 与 immersive system-bar 控制；系统手势区域和系统强制显示行为遵循 Android 版本政策，不保证永久屏蔽系统 UI。
- 正文占据可用屏幕区域；点击屏幕中央呼出工具栏，工具栏可自动隐藏。
- 用户可选择始终显示状态信息、显示页码/进度、屏幕方向、屏幕常亮和阅读边距。
- 退出阅读器后恢复正常应用导航。
- Windows 也支持阅读器全屏与隐藏工具栏，但不强制整个应用始终全屏。
- 沉浸式模式是 Reader Core 的基础能力，插件可提供预设、主题和控件布局，不应成为使用全屏阅读的必要条件。

## 插件可定制范围与核心边界

Reader Core 提供统一的输入事件与导航能力；插件可通过公开 SDK 注册或调整用户可选的 Gesture Profile，包括滚轮、触控板、触摸滑动、边缘点击、键盘和鼠标侧键的映射、灵敏度与动作。插件可以贡献手势预设和阅读工具栏 UI。

建议公开接口包括 ReaderInput / GestureRegistry / GestureProfile。每个映射需声明适用平台、阅读模式、输入设备、优先级、冲突行为和撤销句柄。用户设置优先于插件默认值；插件不能静默覆盖用户映射。核心翻页、文本选择、PDF 缩放、系统返回和无障碍操作具有优先级保护，插件不得拦截系统返回或让基础阅读操作失效。

主题、阅读排版、工具栏、面板、侧栏、Widget 和布局可由主题/布局/UI 插件定制；基础可用的视觉设计、移动端响应式布局、沉浸式阅读和输入事件识别由 Host/Core 保证。未安装任何插件时，所有基础交互仍可用。

# 六-B、视觉方向与设计系统

## 已确认的视觉方向

- **[确定] Reeden 是 Reader 的首要产品与视觉参考。** 以 Reeden 的书架、阅读工作区、导航、主题编辑和统计呈现方式作为主要产品设计依据；重点借鉴内容组织、布局层次、可定制能力与跨设备体验，不复制品牌资产、图标、截图、逐像素布局或具体文案。
- **[确定] 不采用 Material Design 3 / M3 Expressive 作为 Reader 的设计系统基础。** 不要求使用 Incredible MD3 in GPT Skill，不要求使用 MD3 组件、颜色角色、形状规范或 Expressive 表现。UI 应以 Reeden 的产品设计语言为主，建立 Reader 自己轻量、一致的视觉 Token 和组件规则。
- Apple Books 保留为辅助性的阅读体验参考：正文优先、编辑式排版、安静留白和低干扰阅读；当它与 Reeden 的产品布局风格冲突时，以 Reeden 的产品设计方向为准。
- **[确定] 极简的核心是信息克制，不是视觉贫乏。** 界面不出现没有意义的小字、重复说明或装饰性标签；信息层级清晰、文案精炼、留白合理。卡片、圆角、渐变、玻璃/半透明材质、阴影、光效和动画均可成为视觉语言的一部分，允许有质感、有层次、有审美张力的高端表现。设计时重视整体协调、使用场景和阅读舒适度，不做机械化堆砌。
- **视觉主张：** 一个精致、安静、可定制的跨平台数字书房。书架以封面和元数据组织内容；阅读页以正文为主角；Notebook 与统计清晰但不喧宾夺主；主题和插件提供扩展空间，但默认界面无需用户先做大量配置。

## Reeden 产品参考与可借鉴模式

**[确定]** Reader 的产品级 UI 与交互应将 [Reeden](https://reeden.app/cn) 作为电子书阅读器领域的主要参考。Reeden 用于指导书架组织、阅读工作区、主题配置、统计和跨设备导航模式；参考其成熟的产品模式和视觉语言，不要求复刻具体页面或所有功能。

### 参考定位与设计特征

- **整体气质**：内容导向、安静、清晰、可个性化。默认界面以书籍封面、正文排版和阅读进度为主，使用克制的中性色、清楚的文字层级、轻量分隔和适度留白；主题可以增加个性，但不能损害可读性。
- **书架**：同时提供封面网格与信息列表。网格适合日常浏览和发现书籍；列表适合整理元数据、检查标签/分类/字数/文件信息与阅读进度。搜索、快速筛选和排序应靠近书架内容。顶部展示区、继续阅读、最近阅读、统计或封面轮播可作为用户可选模块，不应成为默认的巨大 Hero 区。
- **封面呈现**：保留原始封面比例，允许轻微、可控的封面阴影或书脊细节；真实书籍封面承担视觉识别。仿真书架、封面轮播和书籍打开动画属于可选表现，不作为默认界面的装饰负担。
- **阅读工作区**：正文是视觉主角；工具栏可在需要时浮现或隐藏。平板/桌面可使用侧边目录、书签、笔记等面板与双页/多栏布局；用户可以调整侧栏位置、顺序和显隐。沉浸式阅读不得被应用导航、统计卡片或持续工具栏打断。
- **主题系统**：将「应用主题」与「阅读主题」分离。应用主题管理书架、首页、设置和导航外壳；阅读主题管理正文、纸面背景、字体、高亮和页眉页脚。两者可以提供可选联动，但应能独立设置。阅读主题优先保障长时间阅读的对比度与舒适度。
- **主题编辑**：采用清楚的分区与即时预览，例如「主题 / 排版 / 字体」等类别；颜色选择以色块和语义名称呈现。复杂选项分层放入高级设置，避免把所有设计参数同时暴露给普通用户。
- **导航与响应式布局**：手机使用底部主导航；平板/桌面采用侧边栏或可折叠侧边导航，并在空间不足时支持紧凑模式。页面目的地与功能保持一致，容器随可用窗口尺寸变化。Reader 的沉浸式模式隐藏全局导航。
- **统计**：借鉴以书籍封面、阅读时长、进度条、排名和日/周/月/年切换组织信息；图表应回答明确问题，不把统计首页做成密集 BI 仪表盘。
- **动效与微交互**：可使用有质感的书籍打开动画、页面转场、工具栏浮现、背景/材质变化和细腻反馈，既服务空间关系与操作反馈，也可以增强愉悦感和品牌气质。动效应流畅、节制且不拖慢操作；提供减少动态效果支持。

### Reader 的采用边界

- 默认采用「安静的数字书房」：书架封面清晰、排版精致、背景克制、搜索筛选轻量；阅读页留给正文足够空间。
- 允许用户切换网格/列表、浅色/深色、应用主题/阅读主题和可用的布局密度；提供合理默认值，常用操作不依赖大量前置配置。

- 不复制 Reeden 的品牌资产、专有图标、截图、逐像素布局或具体文案；仅提炼交互模式、信息组织和视觉原则。
- 所有借鉴都必须服从 Reader 已确认的 Local-first、轻量化、插件优先、跨平台和阅读器手势约束；不得为了视觉相似引入重型依赖、常驻服务或破坏 Android 系统行为。

## Reader 自有视觉系统约束

- 实现前先完成简短 Design Brief：视觉主张、主色与中性色角色、字体与字号层级、布局密度、表面层级、形状、图标、动效、浅色/深色策略。先检查方案是否真正符合 Reeden 的产品气质与 Reader 的轻量定位，再开始实现。
- 建立 Reader 自己的语义颜色、字体、间距、圆角、边框、阴影、图标和动效 Token；定义 Light / Dark 两套映射。不得把 MD3 Token、M3 Expressive 或其他现成设计系统作为默认规范。Token 应少而清晰，能够被主题插件安全覆盖。
- 大部分应用表面保持中性或轻微染色；强调色只用于主要操作、选中态和重要状态。阅读纸张主题与应用外壳主题分离，PDF 页面默认保留文档原始颜色。
- 建立清晰字体层级：应用 UI 使用易读的系统字体体系；书名、章节标题和阅读正文可采用更具编辑感的字体。正文支持字体、字号、行距、段距、页边距和阅读宽度设置；不得通过缩小字号解决布局问题。
- 建立有辨识度且一致的间距与形状语言；可使用 4 / 8 dp 基础间距刻度，但不将其包装为 MD3 规范。书籍封面保留内容自身比例。圆角大小和卡片形态可以成为视觉风格的一部分，可根据内容、层级和品牌气质灵活使用；避免缺乏层次变化、所有组件完全相同的机械化处理。
- 综合使用留白、对齐、字体层级、卡片、表面材质、边框、阴影和色彩区分内容与空间层次。渐变、半透明/玻璃材质、光晕、柔和阴影和背景动效均可使用，尤其可以用于营造精致、高级、有纵深的视觉效果；应统一色彩与材质语言，避免彼此冲突或喧宾夺主。
- **极简的文案原则：**主要操作必须容易发现；必要状态、错误恢复、权限说明和无障碍语义必须保留。禁止没有意义的小字、为了填充空间而添加的副标题、装饰性标签和重复说明。书籍作者、阅读进度、文件信息等有实际价值的辅助信息可以保留，并以清晰、可读的层级呈现。
- 动效可以表达状态变化、空间关系、操作反馈，也可以提供适度的视觉愉悦和品牌识别；响应直接操作时保持即时，不得延迟主要操作。支持系统减少动态效果设置。
- 跨平台共享产品身份、语义 Token 和页面结构，但 Android 保持符合平台习惯的导航、系统返回、系统栏与触控行为；桌面端适配鼠标、键盘、触控板和可调整窗口。不能为追求截图一致而强行统一平台行为。
- 主题插件可调整受控的颜色、字体、排版、密度、纸面和组件 Token；UI 插件可扩展工具栏、面板、侧栏与布局。Host/Core 必须提供完整、精致的默认界面；插件缺失时基础阅读体验不受影响。第三方插件不得通过任意全局 CSS 破坏核心布局、可访问性或系统手势。

## 视觉验收流程

- 产品级 UI 实现前先检查实际项目结构和现有组件，形成视觉方案并进行反模板化评审。
- 在可运行环境中启动应用并检查真实截图；至少覆盖小屏手机（约 360 dp）、常见手机（约 390–400 dp）、大屏/平板或桌面窗口，以及 Light / Dark 主题。检查大字体、长标题、真实书籍封面、长文档和空/错误状态。
- 截图检查整体质感、信息层级、字体可读性、对齐、留白、密度、色彩与材质协调、阴影层次、动效状态、控件状态、安全区、滚动可达性，以及是否存在无意义小字和冗余文案；修复后重新截图。只检查代码或静态原型不能算视觉验收。
- 视觉评审以 Reeden 官方产品界面与文档为主要对照，检查书架、阅读页、导航、主题编辑、统计等核心场景；同时检查极简原则是否贯彻。不能仅凭设计稿或代码声称视觉验收通过。

# 七、事件总线

事件按 domain.action 命名，明确类型、Schema 版本和实体 ID。示例：

- app.started/foreground/background/shutdown
- [library.book](http://library.book)-imported/updated/deleted/relocated
- [reader.book](http://reader.book)-opened/closed/location-changed/selection-created/activity/idle
- annotation.created/updated/deleted
- bookmark.created/deleted
- sync.started/progress/completed/failed/conflict-detected
- plugin.installed/enabled/disabled/updated/failed

区分高频 Runtime Event（不持久化，节流/合并）和业务 Domain Event（可持久化/可恢复）。事件 Payload 不直接传输大型书籍二进制。事件订阅必须归属插件生命周期。

# 八、Notebook 插件

Notebook 是独立知识管理模块。**[确定]** 采用 Obsidian 风格：笔记正文以用户可直接访问的 Markdown 文件持久化，支持文件夹、WikiLink 双向链接、反向链接、标签和开放文件结构；不采用必须依赖专有块数据库的 Notion 式编辑模式。Notebook 可脱离当前打开的书籍使用，支持 Markdown 编辑/预览、全文搜索、模板、附件、书籍关联、从选中文字生成笔记、保存引用文本和 ReaderLocation、从笔记跳回原书、书籍关联笔记列表、Markdown 导入导出；知识图谱作为可选 UI 插件。链接解析、笔记重命名时更新链接、相对附件路径以及跨设备同步冲突均需有明确契约。

笔记独立命名空间，正文以普通 .md 文件作为事实来源；SQLite 可保存可重建的全文索引、双链索引、引用定位和辅助元数据。Markdown 编辑器应支持源码编辑与预览。附件以可迁移的相对路径组织。用户在所有平台均能配置本地书库文件夹，Notebook 的默认数据目录可位于其下，且不得强迫使用应用私有且无法导出的笔记库。同步时不能对整篇笔记简单 LWW；可评估 Yjs CRDT、块级合并或冲突副本，必须允许离线编辑、冲突恢复、重复操作去重和历史版本恢复。

# 九、阅读计时与统计

Reading Tracker 监听打开/关闭、前后台、活动、空闲等事件，记录 sessionId、deviceId、bookId、开始结束时间、有效活动时长、起止位置、暂停原因。打开书不代表一直阅读；后台、锁屏和长时间空闲暂停计时；空闲阈值可配置，允许手动修正。Android 使用单调时钟和生命周期事件处理进程挂起，不能依赖后台持续 JS 定时器。

Reading Analytics 单独消费会话，生成日/周/月/年阅读时长、阅读日历、热力图、连续天数、书籍阅读进度、速度、完成率、目标、分类/作者统计、年度报告。统计应能由原始会话重新计算，跨设备会话通过唯一 ID 去重，避免重复累计。

# 十、存储 Provider

Storage Provider 与 Sync Provider 在内部可以保留不同职责接口：前者负责书籍文件对象，后者负责同步文档交换，Sync Engine 负责冲突合并；但两种能力必须绑定到同一个用户选择的 Cloud Provider Profile、Endpoint、账户和凭证。**[确定]** 不允许书籍文件与同步元数据使用不同 Provider，例如不支持书籍文件放 S3、同步元数据放 WebDAV 的混合配置。每个内置 Provider 必须同时实现文件对象与同步元数据所需的能力；用户只需配置一个 Provider。

**[确定]** 首版必备存储 Provider：

- S3-compatible：AWS S3、Cloudflare R2、MinIO、Backblaze B2 等兼容服务，可配置 Endpoint、Region、Bucket、认证信息和路径。
- WebDAV：坚果云、Nextcloud、ownCloud、群晖及通用 WebDAV，支持应用专用密码与自定义地址。
- Local Filesystem：本地书库目录，必须可由用户在 Windows 与 Android 的设置中选取和更改。

**[确定]** Google Drive 和 OneDrive 不是首版交付条件，应通过统一 Provider 插件接口扩展；未来分别采用官方 Drive API / Microsoft Graph API 和适用于原生公共客户端的 OAuth PKCE。内置的 S3、WebDAV 仍必须实现公开的 Provider 契约，不能绕过抽象直接耦合到 Sync Engine。

不要求官方服务器。云 API 需要注册 OAuth 应用或审核，但不等于需要运行 Reader 业务服务器。Provider 接口支持列出、读取、写入、删除、查询元数据、条件写入、范围读取、能力检测、重试、取消和错误分类。不同服务的 ETag、锁和 MOVE 语义不完全一致，必须检测能力并降级。

# 十一、Local-first 同步协议

**[建议]** 参考 LightRead 的 per-device document 设计：每设备有稳定 deviceId，只写自己的同步文档，读取其他设备文档并合并；不在 WebDAV/S3 上共享直接读写一个 SQLite 数据库。

远端逻辑结构：

```
Granite/
  sync/
    protocol-version.json
    devices/<device-id>.json
    manifests/<id>.json
    tombstones/<id>.json
  objects/sha256/<hash>
  plugin-data/<plugin-id>/
```

同步文档包括 protocolVersion、deviceId、revision、变更集合、对象引用、墓碑、插件命名空间和校验信息。Provider 可将逻辑路径映射到非目录型 API。

写入先提交本地 SQLite 和文件，再进入离线同步队列；远端失败不回滚本地。同步必须幂等、可重试、可取消、支持断网恢复、断点续传、分块上传和下载校验。远端损坏不得覆盖本地健康文件。

冲突策略按实体定义：阅读进度依据有效阅读与版本信息合并并保留历史；标签可用 OR-Set；书签与批注以独立 ID 合并；阅读时长使用去重会话或 per-device G-Counter；设置可 LWW；笔记用 CRDT/冲突副本；删除使用 Tombstone，防止离线旧设备复活已删除实体。不能只依赖设备墙上时钟。

**[确定]** 用户执行「删除书籍」时，默认删除云端书籍文件对象及其云端书籍记录，并通过 Tombstone 向其他设备传播删除；不能只移除本地记录而留下云端文件。若 Provider 支持回收站或对象版本控制，应利用其恢复能力并在界面展示。其他设备收到删除墓碑后，清理 Granite 管理的本地同步副本和对应记录；对用户自行管理、仅被索引或外部关联目录中的原始文件，不得未经单独确认就物理删除。移除本地书库根目录仍只解除目录关联，不等同于删除书籍。

**[确定]** 同步策略必须可由用户在设置中配置，至少提供：全量同步书籍文件、仅同步元数据、指定集合/书籍同步、元数据优先并在打开时按需下载书籍文件。界面需显示每本书的云端状态、本地下载/缓存状态和同步进度；切换策略不得把未下载误判为删除，也不得因策略变化自动删除云端文件。未知插件数据必须保留；插件可声明数据 Schema、迁移与合并策略。

# 十二、持久化与安全

本地 SQLite 保存书籍、集合、标签、进度、标注、设备和同步元数据；原始 EPUB/PDF 文件默认放入用户在「设置 → 书库 → 本地书库文件夹」选择的可访问目录；封面、缩略图和解析结果使用缓存；插件数据按命名空间隔离；凭证存操作系统安全设施。活动 SQLite 文件应保留在满足事务和随机访问语义的本机可靠存储中，特别是 Android 不得直接在 SAF Document URI 上运行 SQLite；以开放备份/导出确保数据可迁移。

禁止多个设备直接同步 SQLite 数据库文件。数据库和插件 Schema 必须版本化，迁移失败保留备份并可恢复。高频位置写入节流。插件不允许任意执行 SQL。

S3 密钥、WebDAV 密码、OAuth Token 不写入普通 JSON 或日志；Windows 使用 Credential Manager，Android 使用 Keystore。网络传输 TLS；日志脱敏。**[确定]** Granite 不要求应用层端到端加密（E2EE）或恢复密钥；可使用 Provider 自身提供的服务端加密/静态加密能力，但不把它作为 Granite 自定义密钥体系或跨设备恢复流程。

# 十三、插件生态与数据迁移

插件支持本地文件安装、官方插件目录和第三方插件来源安装、禁用、卸载、更新、版本检查、依赖检查和错误诊断。每个插件提供 Manifest、Bundle、资源、许可证、作者、来源、完整性信息、数据迁移。插件 API 采用版本化契约；弃用接口需要迁移说明。

[确定] OPDS、Calibre、KOReader 集成均作为可选插件实现，不作为 Granite Core 的内置强制功能：OPDS 插件负责目录发现、检索和书籍获取；Calibre 插件负责书库、元数据和文件协作；KOReader 插件负责阅读进度、书签和标注的导入导出或同步。插件详情应说明连接方式、权限、数据方向和兼容版本。

完整导出应包含书籍原文件、元数据、书架、阅读位置、标注、笔记、阅读会话、插件数据、Profile 和布局。凭证默认不导出；若提供加密备份需用户明确选择。导入需要版本校验、重复检测、迁移和冲突预览。用户随时可以离开该应用。

# 十四、质量与验收

## Android GitHub Actions CI/CD（首版要求）

Android 的构建和发布使用 GitHub Actions，流程保持简单：

1. **Pull Request / Push**：运行基本代码检查和已有单元测试，构建 Debug APK；构建成功后上传 APK Artifact。
2. **版本 Tag**（例如 `v1.0.0`）：构建签名后的 Release APK，并自动发布到 GitHub Releases。
3. **签名**：Android Keystore 和密码放在 GitHub Secrets，不提交到仓库。
4. **设备测试**：交付 APK 后，由用户自行手动检查安装、启动、导入书籍、阅读和保存进度。本次开发不执行真机应用验收，也不将其作为发布阻塞条件。

**禁止使用 Android Emulator、模拟器或虚拟设备测试。** GitHub Actions 不运行模拟器测试；本次不执行 Android 真机应用验收。用户后续自行手测。

首版只需发布 APK 到 GitHub Releases，不要求配置 Google Play 自动发布，也不要求额外生成 AAB。

### 首版整体验收

- Windows 安装包成功构建并完成产物检查；实际安装、运行与应用体验由用户后续手测。
- Android 版本由 GitHub Actions 成功构建，完成 APK 签名和产物检查；实际安装运行由用户后续手测。
- 主要阅读、书库文件访问、笔记/标注和基本同步流程已实现并通过适用的自动化检查；真实云存储与跨设备同步由用户后续手测，本次不执行。
- 影响数据安全、应用启动或核心阅读的问题修复后再发布。

# 十六、已确认决策与剩余待确认事项

**已确认**

1. 首版 Core 原生格式：EPUB、PDF、TXT、MOBI；AZW3、CBZ/CBR 可由格式插件扩展。
2. PDF 标注必须直接写回 PDF 文件；至少支持高亮、下划线、文本批注和墨迹注释。
3. 书籍同步策略由用户设置：全量同步、仅元数据、指定集合/书籍、元数据优先并按需下载。
4. 书籍文件与同步元数据必须使用同一个 Provider Profile，不允许跨 Provider 混搭。
5. 不要求应用层 E2EE 或恢复密钥。
6. 插件允许完整自定义 Vue 页面；允许从官方目录、第三方 Registry/Git/URL 和本地包安装插件，并实施来源、完整性、权限与隔离控制。
7. OPDS、Calibre、KOReader 均通过可选插件集成。
8. 主项目许可证采用 AGPL-3.0，按「最开源」理解为最强 Copyleft。
9. 删除书籍默认删除云端文件对象并同步删除墓碑；外部关联目录中的原始文件仍需单独确认才能物理删除。
10. 正式项目名称为 Granite。

**仍待确认**

- PDF 是否必须针对 S Pen、Surface Pen 等触控笔做专门优化（压力、倾斜、掌托、笔橡皮等），还是标准触控墨迹输入即可。
